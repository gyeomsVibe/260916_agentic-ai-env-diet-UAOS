## 3. 기록 순차 정리 로직 (U47-R1, 안티그래비티 구현 · Claude 판정)

"순차"란 **되돌릴 수 있는 단계부터** 차례로 한다는 뜻이다. 삭제는 마지막 단계이고, 사용자 승인 파일이 있어야만 실행된다.

| 단계 | 하는 일 | 되돌리기 | 누가 실행 |
|---|---|---|---|
| 0. 계획 | 영역(zone)별 오래된 파일 목록(기존 `rsi retention`, 건조 실행(dry run)) | 해당 없음 | 누구나 |
| 1. 롤업 | JSONL 장부가 **20,000줄 또는 5MB**를 넘으면 최근 5,000줄만 남긴다. 나머지는 원문 그대로 `.gz`로 압축하고, 다시 읽어 SHA-256을 확인한 뒤에만 본 파일을 줄인다. 요약(`<이름>.rollup.json`)은 영구 보관한다 | `.gz` 풀어 앞에 붙이면 원복 | 누구나(`--rollup-olla`) |
| 2. 보관 | 보관 기간이 지난 파일을 `.coord/retention_archive/<날짜>_<해시8>.zip`에 복사하고 항목별 해시를 확인한다. **원본은 그대로** | zip이 사본 | 누구나(`--archive`) |
| 3. 삭제 | zip과 해시가 같은(보관 뒤 안 바뀐) 원본만 지운다. 바뀐 파일은 건너뛴다 | zip에서 복원 | **사용자만**: `--purge <zip> --approval <파일>` |
| 보고 | `.work/` 하위 폴더를 나이순으로 보고(14일 이상 = 오래됨) | 해당 없음 | 누구나. **이동·삭제 없음**(전역 규칙: 추적 안 되는 폴더는 옮기거나 지우지 않는다) |

숫자의 이유:

- **20,000줄**: 현재 하루 144줄이면 약 4.5개월치다. **5,000줄**은 최근 약 35일치를 원문으로 남겨 RSI 분석에 쓴다.
- **5MB**: 장부 전체를 매번 읽는 명령(`olla` 통계, 훅)이 1초 안에 끝나는 크기다.
- **보관 30일**: `.coord/runs`, 우편함 `ack`·`claimed`. 실패(FAILED)·P1·승인 기록은 기간과 상관없이 보호한다(U42-R1 규칙 유지).
- **승인 파일**: `{"approver": "user", "action": "purge", "manifest_sha256": "<zip의 해시>"}`.
  - 이름표는 인증이 아니다(B83). 그래서 에이전트는 이 명령을 실행하지 않는다는 운영 규칙을 함께 둔다.

언제 돌리나: 예약 폴링은 하지 않는다.

- 세션 시작 훅이나 교환원(sentinel)이 `rsi retention`(건조 실행)을 보고, 한도를 넘었을 때만 한 줄로 알린다.
- 이 알림 연결은 후속 카드 U47-R2다.

## 4. Claude 사용량 조절 규칙

- 측정은 `get_usage`(앱 사용량 카드)로 한다. 18:1x 기준: 5시간 창 3%, 주간 13%, 문맥 10%.
- 속도 조절:
  - **5시간 창 < 60%**: 정상 진행. Claude는 설계·판정만 하고, 구현은 `worker: apply`(0토큰) 또는 안티그래비티가 한다.
  - **60~85%**: 새 장문 단계를 열지 않는다. 판정 대기 번들만 끝내고, 요약·추출은 올라마로 돌린다.
  - **> 85% 또는 주간 > 80%**: 멈춤 인계문(카드·채널)만 쓰고 종료한다. 안티그래비티가 이어받는다(docs/47 승계 규칙).
- 판정 예약량: 번들 하나를 판정하는 데 Claude 약 1~3%(전체 테스트 1회 + diff 읽기)를 남겨 둔다.
