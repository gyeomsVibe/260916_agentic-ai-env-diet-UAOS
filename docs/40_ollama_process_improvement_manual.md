- 상태: 유지(maintained) 정본 매뉴얼 v1, 2026-09-24
- 상위 규약: `AGENTS.md`, `docs/01` §17~§18, `docs/24`, `docs/27`, `docs/31`
- 제정 주체: Antigravity 권한대행 (Codex 부재 중 사용자 지시 무승인 발행)

## 1. 올라마의 본질적 위상 (영구 불변식)

1. **생각 없는 단순 도구인 전자계산기 (Calculator)**:
   - 올라마는 스스로 생각하거나 계획을 세울 수 없으며, 전략적 가치 판단이나 설계 능력이 없는 100% 무비용 연산 도구다.
   - 사용자가 머릿속에 세운 구상과 계획 프로세스를 실행할 때 유료 LLM의 API 토큰을 방어하기 위한 '토큰절약도구'다.
2. **원할 때 언제든지 쓰는 유선 전화기 (Telephone)**:
   - 평소에는 유휴 상태로 대기하다가 지휘자(Codex, Claude Code, Antigravity)가 다이얼을 걸어(명령어 호출) 즉시 응답을 받는 통화료 0원의 유선 전화기다.
   - 유료 LLM의 주기적 상주 폴링(cron)은 통화료가 나가는 위성전화를 켜놓는 낭비이므로 영구 금지한다.
   - 디스크 우편함(`.coord/mailbox/`)은 0원 '음성사서함'으로 기능하며, 로컬 올라마 기반 상주 감시관(Sentinel)은 24/7 '교환원'으로서 상태 감시를 수행하다 차단 결함(P1) 발생 시에만 1회 기상벨을 울린다(Wake-on-P1 Ringing).
3. **판정권 완전 배제**:
   - 올라마는 자신의 성공/실패 여부를 판정할 수 없다. 오직 결정론적 인수 테스트(Acceptance Gate)와 지휘자의 diff 검증만이 판정한다.

## 2. 작업명령서 작성 5대 규칙 (구체성 80점 표준)

올라마에게 작업을 위임할 때는 반드시 `docs/24` 표준 템플릿을 준수해야 하며, 아래 5대 요건을 충족해야 한다.

1. **단일 파일 격리 (Single File Scope)**:
   - 한 번의 호출에는 반드시 대상 파일 1개만 지목한다 (`--source`를 좁혀 staging 루트에 1개 파일만 배치).
2. **명확한 EDIT 블록 헤더**:
   - 반드시 `===EDIT: <파일명>===` 형식으로 시작해야 한다.
3. **바이트 단위 정확한 SEARCH 블록**:
   - `<<<<<<< SEARCH` 와 `=======` 사이의 텍스트는 원본 파일과 공백·들여쓰기까지 100% 바이트 단위로 일치해야 한다.
   - 모호한 자연어 지시나 부분 발췌를 금지한다.
4. **결정론적 REPLACE 블록**:
   - `=======` 와 `>>>>>>> REPLACE` 사이의 교체 텍스트는 모듈 임포트(`import time`, `import os` 등 로컬 스코프 포함)를 완비해야 한다.
5. **결정론적 인수 테스트 스크립트 결합**:
   - 프롬프트와 함께 실행될 독립 검증 스크립트(`accept.py`)를 절대 경로로 지정하여 실행 1회에 성공/실패를 기계적으로 판정한다.

## 3. 올라마 실사용 데이터 자동 축적 및 개선 루프 (RSI)

모든 파일럿 실행은 `.coord/usage/runs.jsonl`에 v2 영수증을 남긴다. 직접 `olla` 호출의 원시 이벤트는 전역 `OLLA_USAGE` JSONL에 남고, pilot 안의 Ollama 호출은 프로젝트 장부에도 같은 작업 ID로 기록한다. 두 장부를 합칠 때 중복 집계하지 않는다.

### 기록 필드 표준 (v2 스키마)
```json
{
  "schema": "uaos-usage-v2",
  "work_id": "U27-OLLA-01",
  "actor": "antigravity",
  "model": "qwen2.5-coder:7b",
  "kind": "pilot",
  "collection_mode": "automatic",
  "input_tokens": 2272,
  "output_tokens": 245,
  "wall_time_s": 24.1,
  "outcome": "PASS",
  "receipt": ".work/pilot_U27/runs/U27/summary.json",
  "independent_verifier": null,
  "rsi_eligible": false,
  "exclusion_reason": "PENDING_INDEPENDENT_VERIFICATION"
}
```

### 10회 주기 프로세스 개선 절차
1. **분모 전수 보존**: 실패(`REWORK`), 차단(`BLOCKED`), 격리 위반(`EXTERNAL_WRITE`)을 포함한 모든 착수 시도를 분모에 기록한다.
2. **지표 비교**:
   - 성공률 (Pass Rate)
   - 재작업률 (Rework Rate)
   - 평균 벽시계 시간 (50/80 백분위수)
   - 프롬프트 구체성 점수 대비 실패 패턴 분석 (예: `EDIT_SEARCH_NOT_FOUND` 발생 원인 분류)
3. **프롬프트 템플릿 자동 튜닝 및 실측 반례 피드백**:
   - `EDIT_SEARCH_NOT_FOUND`가 발생하면 파일 전체를 검색하는 대신 주변 함수 5줄을 포함한 확장 SEARCH 블록을 자동 생성하도록 템플릿 개선.
   - `NameError`가 발생하면 메서드 내부 로컬 임포트 스코프 자동 검증기 추가.
   - **백틱 파일명 필수 규칙 (2026-09-24 실측 반례)**: 프롬프트에 백틱(`` `v7_harness/olla.py` ``)이 누락되면 작업자 정규식이 파일명을 인식하지 못해 150줄 이상 파일임에도 `FORMAT_RULES`(전체 재작성)로 오분류되어 코드가 잘리는 결함 발생. 반드시 대상 파일명을 백틱으로 감싸야 함.
   - **대형 파일(>60KB) 컨텍스트 스케일링 (2026-09-24 실측 반례)**: 1,000줄 이상의 대형 파일 수정 시 16k 컨텍스트 제한(`limit = 12288`)으로 인해 `PROMPT_TOO_LARGE`가 발생하므로, 환경변수 `OLLAMA_WORKER_NUM_CTX=32768`을 주입하여 32k 컨텍스트로 스케일업 실행함.
