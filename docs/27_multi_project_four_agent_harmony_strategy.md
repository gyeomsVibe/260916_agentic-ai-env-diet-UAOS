## 3. 타 5개 프로젝트 연동 다이어트 아키텍처

### 3.1. 문제점: 프로젝트별 환경 복제 시 발생하는 토큰/디스크 낭비
- 5개 프로젝트마다 각각 대형 가상환경, 중복 규칙, 상주 프로세스를 띄우면 호스트 RAM/GPU 고갈 및 토큰 낭비가 5배로 폭증함.

### 3.2. 해법: "단일 0원 디스크 우편함 버스 + 공유 경량 하네스"
1. **공용 비동기 우편함 통신 버스**:
   - `260916_agentic-ai-env-diet`의 검증된 `.coord/mailbox/` 구조를 타 5개 프로젝트와 심볼릭 링크 또는 공용 경로(`D:\D_Workspace_NB\-agentic-ai-workspace\.coord\mailbox\`)로 연결.
   - 각 프로젝트의 상태 보고와 작업 요청을 디스크 파일(0원)로 송수신.
2. **로컬 올라마 1개 인스턴스로 5개 프로젝트 전수 감시 (Sentinel)**:
   - 상주 감시관(`v7_harness/coord/sentinel.py`)이 5개 프로젝트의 `.work/QUIET_LOCK`과 스트림 로그를 순회 감시하여, 차단(BLOCKED P1) 발생 프로젝트만 지휘자에게 알림(Wake-on-P1).
3. **지휘자의 1턴 통합 섭취**:
   - Codex는 5개 프로젝트를 일일이 열어보지 않고, 올라마가 생성한 "5개 프로젝트 통합 60줄 브리핑" 1개만 읽고 우선순위가 가장 높은 과제 1개만 골라 지휘.

## 4. Antigravity가 코덱스에게 즉시 제공할 수 있는 3대 지원 작업

1. **[지원 1] 5개 프로젝트 구조 및 규칙 0원 요약본 제공**:
   - 로컬 올라마(`olla digest`, `local_read_map`)를 구동하여 5개 프로젝트의 현재 상태, 진척도, 주요 파일을 0원에 초압축 요약하여 코덱스에게 1턴 데이터로 제공.
2. **[지원 2] 4자 분업 실행 매뉴얼 초안 검증 및 반례 테스트**:
   - Codex가 작성할 분업 운영 규칙에 대해 Antigravity가 하네스 기반 독립 검증(Red-Team Test)을 수행하여 빈틈 없는 정본으로 확정.
3. **[지원 3] 고난도 격리 파일럿 대행**:
   - 코덱스의 토큰이 부족할 때, 엄격한 인수 테스트 게이트가 동봉된 단일 파일럿 작업을 Antigravity가 고립 환경에서 1턴에 완결하여 결과만 전달.
