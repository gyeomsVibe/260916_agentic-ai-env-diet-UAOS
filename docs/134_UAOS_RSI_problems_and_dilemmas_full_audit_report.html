난제 1 위임 작업자 통과율의 역설 (Worker Pass-Rate Paradox)

현상: "Ollama(계산기)와 저비용 모델(Gemini Flash/Haiku)이 구현하고, 고비용 모델이 최종 판정한다"는 운영체제의 핵심 설계가 현장에서 정상 작동하지 않았습니다. 최근 10회 기준 Antigravity 위임 통과율은 10%, Ollama는 20%, Claude 워커는 0%에 그쳤습니다.

근본 원인: 모델의 지능 부족이 아닌 ‘계약 매뉴얼과 하네스 마찰’ 때문입니다. 허용 경로 밖 임시 파일 쓰기 감시(EXTERNAL_WRITE 10회 이상 재발), 20줄 초과 슬라이스 시 발생하는 PROMPT_TOO_LARGE, 그리고 윈도우 환경 파일 잠금 충돌이 자동 실패를 유발했습니다. 결국 20줄 이하 직접 패치(apply)만이 유일하게 80% 통과율을 기록하며 ‘위임 자동화’가 무색해지는 난제가 발생했습니다.

난제 2 토큰 절약 목표의 미측정 (Unmeasured Savings & Fixed-Context Bloat)

현상: 300여 개 카드를 개발·운용했음에도 불구하고, 실제 "운영체제 도입 전 대비 유료 토큰/구독 잔여량 절감액"이 장부상 여전히 UNMEASURED 상태로 남아 있습니다.

근본 원인: 엄밀한 대조군(Before/After Snapshot Pair) 수집이 누락되었으며, 오히려 운영체제를 유지하기 위한 고정 컨텍스트가 토큰을 잠식했습니다. .coord/PLAN.md가 628줄(233 KB)까지 비대해졌고, 글로벌 규칙과 에이전트 지침 등 세션 시작마다 5만~7만 토큰의 컨텍스트를 강제 로딩하여 절약 효과를 스스로 상쇄하는 병목이 존재합니다.

난제 3 단일 진실 공급원(Single Source of Truth)의 분열

현상: 도구 간 상태 불일치로 인해 지휘권 오판독 및 레거시 코드로의 역행 위험이 상존했습니다.

  • 출석(Presence) 왜곡: Codex가 쿼터 소진으로 멈췄음에도 하트비트 파일상 ACTIVE로 남아 있어 실시간 지휘권 라우팅이 Codex를 계속 호출하려 시도함.
  • 이중 조율 기저: SQLite DB(coord.sqlite3)와 파일 시스템 메일박스(.coord/mailbox/*.json)가 공존하며 상태가 어긋남.
  • 루트 워크스페이스 드리프트: 프로젝트 루트 디렉터리가 최신 main이 아닌 과거 브랜치(claude/u181-boot, 변경점 102개)에 방치되어 루트에서 실행하는 하네스 명령이 최신 코드를 인식하지 못함.

난제 4 정지 관문(Stop-Gate) 과열 피로 및 레이스 컨디션

현상: 비정상 종료를 방지하기 위해 도입된 정지 관문(Stop Gate)이 오히려 에이전트를 가두는 감옥 역할을 했습니다. stop_gate.jsonl에 269건의 차단이 쌓였고, U180 카드의 경우 단일 카드가 무려 62회나 반복 차단되었습니다.

근본 원인: 동일한 상태임에도 불구하고 상태 해시(State Hash) 기반 중복 제거가 없어 감시 프로세스가 끊임없이 깨어났습니다. 또한 Windows 환경에서 메일박스 공지 파일 생성 시 하드링크 및 아토믹 교체 충돌(WinError 183, O_APPEND 비원자성)이 발생하여 에이전트 간 티키타카가 일시 정체되는 문제가 실측되었습니다.

난제 5 자원 팽창(Sprawl)과 안전 경계(Safety Boundary)의 충돌

현상: 카드 격리 세션이 가동될 때마다 워크트리와 디렉터리가 기하급수적으로 증식했습니다. 현재 등록된 Git 워크트리만 274개, .work/ 내 디렉터리가 792개, Claude 워크트리가 58개에 달합니다.

근본 원인: "데이터 삭제, 배포, 결제, 설정 변경은 반드시 사용자 명시 승인을 받는다"는 철칙(Safety Boundary)으로 인해, 병합이 끝난 오래된 워크트리라도 에이전트가 독단으로 rm -rf 할 수 없습니다. 이로 인해 청소 로직은 매니페스트 생성(deleted_count: 0)까지만 멈추게 되어 디스크와 인덱스 스캔 부하가 누적되었습니다.
