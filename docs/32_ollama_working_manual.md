# 로컬 올라마(Ollama) 작업명령 매뉴얼 및 전화기·계산기 통합 아키텍처 규약

- 문서 번호: `docs/24`
- 버전: `v2.0.0` (2026-09-24 사용자 지정 고정 규약 전면 반영)
- 수신: 로컬 올라마 (`qwen2.5-coder:7b`), 3대 지휘 도구 (Codex, Claude Code, Antigravity)
- 성격: **비용 0원 프로그래머블 일꾼(전자계산기)·유선 전화기(Telephone) 및 24/7 상주 감시관(Sentinel) 상세 행동 규약**

---

## 1. 역할 정의 및 4대 절대 불변식 (Invariants)

1. **생각 없는 단순 도구 전자계산기 (Brainless Calculator)**:
   - 올라마는 스스로 생각하거나 계획을 세우지 못하는 **생각 없는 단순 도구인 전자계산기**이다.
   - 사용자가 머릿속에 계획을 세우고, 그 계획 프로세스를 수행할 때 두드리는 계산기에 불과하다.
   - 독자적 설계, 주관적 추론, "알아서 개선" 식의 창작은 원천 금지되며, 오직 입력된 정확한 지시문(수식)에 따라 결정론적 텍스트(계산 결과)만 출력한다.

2. **언제든지 원할 때 쓰는 0원 유선 전화기 (Zero-Cost Landline Telephone)**:
   - 올라마는 책상 위에 항상 놓여 있어 우리가 원할 때 수화기를 들고 다이얼을 돌려 바로 쓰는 **유선 전화기**이다.
   - 전화기는 자기가 먼저 말을 걸지 않는다. 평소에는 대기(Listening)하고 있다가, 지휘자가 번호를 누르면(명령 호출) 즉시 연결되어 용건을 처리한다.
   - 통화료(토큰 비용)는 영구히 0원이다. 분당 요금이 폭증하는 위성전화(유료 API)를 24시간 켜놓고 폴링하는 모순을 영구 배제한다.

3. **3대 도구의 토큰절약도구 (Zero-Token Budget Defense)**:
   - 올라마는 Codex, Claude Code, Antigravity 3대 도구의 유료 API 토큰 예산을 보존하기 위한 **공통의 단순 노동 일꾼**이다.
   - 파일 구조 지도(`local_read_map`), 마크다운 요약(`olla digest`), 서식 변환, 테스트 스텁 생성, 로그 분류, 반복 편집은 유료 토큰 사용 전 반드시 올라마에게 먼저 넘긴다.
   - 3대 지휘 도구가 일꾼을 부리지 않고 유료 토큰을 낭비하는 것은 중대한 아키텍처 설계 결함으로 판정한다.

4. **판정권 0 (Zero Verdict Authority)**:
   - 올라마는 자신의 성공이나 실패를 스스로 판정하지 못한다 ("제가 코드를 완벽히 수정했습니다" 등 자의적 판단 금지).
   - 오직 하네스의 결정론적 인수 테스트(Acceptance Gate)와 외부 diff 검증기만이 성공/실패를 판정한다.

## 2. 전화기 아키텍처 모델 (The Telephone Architecture Model)

```
       [지휘자 (Codex / Antigravity / Claude)]
                   │             ▲
      다이얼 (Dial) │             │ 수화기 응답 (Receiver)
       (명령 호출)  │             │ (0원 즉시 연산)
                   ▼             │
             ┌─────────────────────────┐
             │   로컬 올라마 (Ollama)  │
             │   "비용 0원 유선 전화기" │
             └─────────────────────────┘
                         │
        부재 시 메시지 기록 │ (비동기 스풀링)
                         ▼
             ┌─────────────────────────┐
             │ 음성사서함 (Voicemail)  │
             │ 디스크 기반 .coord/mailbox/ │
             └─────────────────────────┘
                         ▲
                         │ 24/7 상태 점검 (비용 0원)
             ┌─────────────────────────┐
             │ 상주 감시관 (Sentinel)  │
             │  (규칙 기반 교환원·모델 호출 없음)   │
             └─────────────────────────┘
                         │
                P1 결함 시에만 벨 울림
                  (Wake-on-P1 Ringing)
                         ▼
             [지휘 도구 1회 선별 기상]
```

### 2.1. 다이얼 (Dialing): 지휘자의 호출
- 지휘자는 필요할 때만 CLI나 프로세스 호출로 올라마의 수화기를 울린다.
  - 단건 질의/요약: `olla ask -f <파일> "<구체적 지시>"`
  - 코드 구현 위임: `python -m v7_harness.cli pilot run --task <ID> --source <dir> --worker local --prompt-file <md> --accept-cmd "<테스트>"`
  - 구조 지도 작성: `python -m v7_harness.cli map <파일>`

### 2.2. 수화기 (Receiver): 올라마의 즉각 응답
- 지휘자의 호출이 오면 로컬 GPU/CPU 자원만을 사용하여 즉시 응답을 반환한다.
- 응답에는 감정, 사설, 변명, 서술형 잡담을 일절 포함하지 않으며 오직 요구된 코드 블록 또는 데이터만 반환한다.

### 2.3. 음성사서함 (Voicemail): 0원 디스크 우편함 (`.coord/mailbox/`)
- 지휘자가 작업 중이거나 부재 중일 때의 비동기 메시지는 디스크 우편함에 남긴다.
- 원자적 파일 쓰기(`tmp/` -> `inbox/`)로 잠금 없는 100% 무손실 비동기 큐를 유지한다.
- 네트워크나 외부 서버를 거치지 않으므로 데이터 유출 위험 0, 토큰 비용 0이다.

### 2.4. 교환원 (Operator / Sentinel): 24/7 상주 감시관
- 로컬 올라마 프로세스는 백그라운드 교환원으로서 0원 비용으로 우편함, 잠금 파일(`.work/QUIET_LOCK`), 스트림 로그를 24시간 감시한다.
- 유료 LLM을 깨우지 않고 60분 초과 고착 잠금, 1차 에러 트리아지(`CODE`/`INFRA`), 60줄 초압축 브리핑 생성을 전담한다.
- 차단 결함(`BLOCKED P1`)이나 사용자 명시 승인 경계에 도달했을 때만 지휘자의 벨을 울려(Wake-on-P1) 1회 선별 기상시킨다.

## 3. 세밀한 작업명령서(Detailed Work Order) 작성 규약

올라마는 생각 없는 전자계산기이므로, 엉성하거나 추상적인 지시를 내리면 잘못된 계산 결과를 출력한다.
지휘자(Antigravity / Codex)는 올라마를 호출하기 전 반드시 아래 기준을 충족하는 세밀한 작업명령서를 작성해야 한다.

### 3.1. 구체성 80점 이상 필수 기준 (Specificity Score >= 80)
1. **수정 대상 단일 파일 절대/상대 경로 명시** (1개 작업당 원칙적으로 1개 파일).
2. **정확한 SEARCH 블록 제공**: 수정할 기존 코드의 시작과 끝을 오차 없이 100% 일치하도록 제시.
3. **정확한 REPLACE 블록 제공**: 새로 들어갈 코드를 완전한 형태로 제시.
4. **외부 의존성 및 함수 시그니처 사전 정의**: 임포트할 모듈과 파라미터 타입을 지시서에 확정.
5. **독립된 인수 테스트(Acceptance Gate) 코드 사전 첨부**: 성공 여부를 판정할 테스트 스크립트 명시.

### 3.2. 지시문 비교표

| 구분 | 나쁜 지시 (금지, 구체성 < 60) | 좋은 지시 (권장, 구체성 >= 80) |
| :--- | :--- | :--- |
| **태도** | "성능을 적절히 개선해줘" | "함수 `parse_data`의 루프를 리스트 컴프리헨션으로 변경해줘" |
| **범위** | "알아서 파일들을 찾아서 고쳐봐" | "대상 파일은 `v7_harness/coord/notify.py` 1개다" |
| **위치** | "중간쯤에 있는 에러 처리를 보강해" | "`SEARCH:` 블록의 140행부터 145행을 `REPLACE:` 내용으로 바꿔" |
| **판단** | "가장 좋은 아키텍처 패턴을 골라서 구현해" | "아래 제공하는 인터페이스 규격대로 클래스를 작성해" |

### 3.3. 세밀한 작업명령서 표준 템플릿

```markdown
# 작업명령서: [작업 ID]

## 1. 대상 파일
- 파일 경로: `relative/path/to/target.py`

## 2. 작업 방식
[A형 전체 파일 교체] 또는 [B형 국소 블록 치환]

## 3. 세부 수정 블록
===EDIT: relative/path/to/target.py===
<<<<<<< SEARCH
def existing_function(arg1):
    # 기존 코드 블록
    return False
=======
def existing_function(arg1, flag: bool = True):
    # 신규 코드 블록
    if flag:
        return True
    return False
>>>>>>> REPLACE

## 4. 금지 사항
- 설명, 인사말, 마크다운 펜스(```) 추가 출력 금지.
- 오직 ===EDIT: 형식만 출력할 것.

## 5. 인수 판정 게이트 (지휘자가 실행)
- 실행 명령: `python -m unittest tests/test_target.py`
- 판정 기준: exit code 0
```

## 4. 안티그래비티–올라마 분업 실행 매뉴얼

### 4.1. 안티그래비티 (지휘자 / 오케스트레이터)의 책무
1. **계획 및 전략 수립**: 사용자의 요구를 분석하여 `.coord/PLAN.md`에 단계를 정의한다.
2. **지시명령서 작성**: 올라마가 생각할 필요가 없도록 구체성 80점 이상의 세밀한 작업명령서를 작성한다.
3. **인수 게이트 작성**: 구현에 앞서 결과를 객관적으로 검증할 인수 테스트 코드를 먼저 작성한다.
4. **결과 검증 및 diff 판정**: 올라마가 반환한 결과를 받아 인수 테스트를 돌리고 diff를 확인하여 최종 `APPLIED` 여부를 승인한다.
5. **Codex 부재 시 대행**: Codex 부재 중에는 조율자 역할을 대행하되, `verdict_requested=no`를 유지하여 큐 오염을 방지한다.

### 4.2. 올라마 (일꾼 / 전자계산기 / 유선 전화기)의 책무
1. **지시문 충실 실행**: 전달받은 작업명령서의 SEARCH/REPLACE 블록을 한 글자의 오차도 없이 파일에 반영한다.
2. **출력 형식 준수**: 불필요한 서술이나 자평 없이 정해진 형식(`===FILE:` 또는 `===EDIT:`)만 반환한다.
3. **비용 0원 방어**: 로컬 연산 자원만 소모하고 유료 API 호출을 0건으로 유지한다.
4. **상주 감시 수행**: Sentinel 모드에서 24시간 우편함과 잠금 상태를 감시하고 60줄 초압축 브리핑을 갱신한다.

## 5. 부재 중 신호 및 대화창 편입 규약

1. **Codex 부재 시 대화창 메시지 발송 전면 금지 (HARD REFUSE: `CODEX_ABSENT`)**:
   - `.coord/PLAN.md`에 `codex: LIMITED` 또는 `codex: ABSENT`가 기록되어 있을 때, Codex 대화창 및 메시지 큐(`coord notify`, `codex queue`)로의 발송은 100% **전면 거부(하드 차단)**된다.
   - 한도 초과 상태인 Codex 대화창에 메시지가 유입되어 한도 에러 화면을 유발하거나 큐를 오염시키는 행위를 원천 차단한다.
   - 모든 진행 상황은 비용 0원 디스크 우편함(`.coord/mailbox/`) 및 브리핑 파일(`.coord/codex_brief.md`)에만 비동기 스풀링하며, Codex 복귀 전까지 대화창 발송을 일절 하지 않는다.

2. **Codex 활성 대화창 편입 표식**:
   - Codex 복귀 후 정상 통지 시, 모든 보고 메시지의 첫머리는 `[안티그래비티에서 온 대화]`, `[클로드에게서 온 대화]` 표식을 달아 Codex 데스크톱 UI에서 발신 주체를 즉시 식별할 수 있도록 한다.
