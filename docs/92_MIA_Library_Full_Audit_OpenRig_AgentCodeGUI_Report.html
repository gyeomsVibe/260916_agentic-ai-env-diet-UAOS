3.2 핵심 도메인 메커니즘 (코드 원문 실측)

  • SessionTransport & 15초 신선도 게이트 (session-transport.ts, 4,051줄):
    • SEND_READINESS_FRESHNESS_MS = 15_000: 훅 활동 기록이 15초를 넘으면 "지금 전송해도 안전한가"의 근거로 쓰지 않고 실시간 tmux capture-pane 프로브로 폴백.
    • MID_WORK_PATTERNS(스피너, Working, esc to interrupt)와 PERMISSION_PROMPT_PATTERNS(Do you want to proceed 등)를 구분하여 작업 중이거나 권한 질문 대기 중인 창에 메시지를 덮어쓰지 않음.
  • SeatDeliveryGuard (seat-delivery-guard.ts, 462줄):
    • AsyncLocalStorage 기반 직렬화 도메인 + TYPING_GUARD_MODES = ["off", "draft-aware", "hold"]. 사용자가 터미널 입력창에 초안을 타이핑 중일 때 에이전트 자동 배달이 입력을 깨뜨리는 현상을 방지.
  • QueueWakeLadder (queue-wake-ladder.ts, 1,342줄):
    • 핵심 불변식: "THE ROW CARRIES THE OBLIGATION EXACTLY-ONCE; THE WAKE IS AT-LEAST-ONCE."
    • 배턴(인계 작업) 기상 실패 시 침묵 주차(silent park)를 금지하고, retry(기본 3회, 300초 간격) → orchestrator 집계 에스컬레이션 → operator 표면으로 승격하며 모든 위치를 DB 전이 로그에서 유도(재시작 시 카운트 리셋이나 망각 방지).
    • 사용량 한도(Usage Limit) 해제 시 30~90초 지터(Jitter)를 두어 동시 기상 폭주(thundering herd) 차단.
  • Watchdog 트랜잭션 다이제스트 (watchdog-delivery.ts, 129줄):
    • bindDigest가 단일 SQLite 트랜잭션 안에서 모든 멤버의 outbox 항목을 guard-watchdog-<id>로 선점(claim)한 뒤 1회만 전송하여 중단 후 중복 발송을 원천 차단.
  • 8대 동맥(Arteries) 및 시드 회귀 규율 (docs/as-built/arteries.md):
    • 작은 변경이 대형 회귀를 부르는 8개 핵심 구역(메시지 배달, 런치/재개, 큐 픽업/기상, Rig 신원, 스킬 투영, 네이티브 프로세스 ps 관측, 마이그레이션, 복구)을 명시하고, 동맥 수정 시 반드시 정상 통과 + 결함 주입(seed_regression) 실패 쌍 시나리오를 요구.
