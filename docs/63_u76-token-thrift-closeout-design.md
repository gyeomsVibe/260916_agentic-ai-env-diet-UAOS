# U76 토큰 절약 종결 설계

## 현재 판정

- 기능 관문: 최신 main `206eed9`에서 비용·연속성·장부·RSI·병합 관문 집중 시험 59개가 통과했다.
- 비용 관문: U74 카드가 기준 카드 평균의 3.14배여서 U72는 FAIL이다. 프로젝트 완성 주장은 아직 거부한다.
- Ollama: `list_extract`만 현재 모델 digest에서 QUALIFIED이고 `verbatim_quote`는 REJECTED다. 결정적 AST·해시·검색이 먼저다.
- 세 도구: Claude와 Codex의 로컬 호출은 실측됐지만 Antigravity는 LIMITED라 U48-M1의 세 도구 실세션 관문은 아직 UNKNOWN이다.

## 다음 순서

1. U76-A: 기존 장부를 보존한 채 통제 대조 쌍만 계산하는 결정적 보고기를 만든다. 입력 해시·인수 해시·작업유형·모델이 같고, baseline과 thrift 모두 PASS이며 독립 판정자가 있는 쌍만 절감으로 센다. 없으면 `UNMEASURED`다.
2. U76-B: 오래된 표본은 삭제하거나 임의의 14일 반감기를 적용하지 않는다. 최근 유효 대조 10쌍만 판정 창에 쓰고 이전 쌍은 감사 이력으로 남긴다. 이 10은 기존 U55/U56 관문과 같은 수다.
3. U76-C: 한 카드에는 부분 작업 하나만 둔다. 카드 경계마다 세션 사용량을 기록하고 3배 회귀면 다음 카드를 열지 않는다.
4. U76-D: Antigravity가 ACTIVE로 돌아왔을 때만 새 세션 Ollama 호출을 1회 검증한다. LIMITED 상태에서는 유료 폴링 없이 우편함 감시만 유지한다.
5. U76-E: 유효 대조 10쌍, P1 0, 품질 저하 0, 카드별 3배 회귀 0을 동시에 만족할 때만 U55·U56·U72를 종결한다.

## 도구별 절약 역할

- Codex: 계획·순서·최종 판정과 반례 한 건에 집중한다. 저장소 전체 대신 해시 고정 패킷과 diff를 읽고 카드당 유료 판정 차례를 1회로 제한한다.
- Claude Code: 한 카드·한 부분 작업의 구현자다. 기계적 수정은 `worker: apply` 또는 자격을 통과한 local로 보내고, 카드 시작·끝에 세션 장부를 남긴다.
- Antigravity: ACTIVE일 때만 외부 조사·브라우저·독립 검토를 맡는다. Codex·Claude가 ACTIVE이면 소스 구현을 중복하지 않는다.
- Ollama: 결정적 도구로 끝나지 않는 좁은 기계 작업만 수행한다. 현재 허용은 `list_extract`; `verbatim_quote`와 JSON 자유 생성은 거부한다.

## 승인 경계

로컬 문서·PLAN·시험·드라이런은 연속 수행한다. push, deploy, 시스템 설정, 삭제, 결제, 계정·자격증명·권한 변경은 과거 승인에서 이전하지 않고 각각 최신 명시 승인을 기다린다.
