## 1. 왜 기존 모델 선정과 역할 고정이 실패하는가?

1. **선정 시점 괴리 (Recency Drift)**: 기존 레지스트리(`U304-B`, 11월 4일)는 `GPT-6.1 Sol`, `GPT-6 Astra`, `Gemini 4 Argon`, `Gemini 3.5 Flash-Lite`(일부 레거시는 `Gemini 3.8 Flash`)에 멈춰 있으나, 11월 24일 현재 실측 환경과 공식·벤치 자료에는 `GPT-6.2 Sol/Astra`, `Gemini 4 Neon`, `Gemini 4 Hydrogen`, `Orchestrator (Neon/Carbon)`이 이미 가용하다.
2. **"단가 싼 모델 = 총비용 절감"의 착시 (Retry Tax)**: `Gemini 3.8 Flash`(AA `31`)처럼 토큰 단가가 낮아도 출력이 장황하고 복잡한 코드베이스 지시를 누락해 `3~5`회 재시도 컨텍스트 재전송이 발생하면, **성공 1건당 총 소모 토큰(`토큰/성과`)** 은 `Orchestrator (Neon)`·`Gemini 4 Neon`·`GPT-6.2 Sol/Astra`·`Claude Opus 5.5` 한방보다 오히려 커진다.
3. **고정 역할 핀의 위험 (Static Position Trap)**: "AGY=노동력, Codex/Claude=두뇌"는 현재(`2026-11-24` AI Ultra Pool B `98%` vs Claude `1%`/Codex `28%`)에서 최적이지만, 주간 리셋·할당량 급감·요금제 변경 시 즉시 역전될 수 있으므로 **영구 고정이 아닌 5h/7d 기반 동적 포지션 이동**이 필수다.

## 2. `성과/토큰` (`Performance-per-Token`) 및 `Cost-of-Pass` 근거 논리

- **핵심 학술·사용자 근거**:
  - 사용자 자료(`0. 성과-토큰.png`): 모델 가성비·선정 기준은 **성과/토큰**(높을수록 우수)이며, 비용 산출은 **토큰/성과**(낮을수록 우수)로 측정한다.
  - *Cost-of-Pass* (Erol et al., `arXiv:2504.13359`): 기대 성공 비용 $= \text{Cost} / \text{Accuracy}$. 약한 모델의 다중 재시도는 실패 문맥 누적(Retry Tax)과 상위 모델 에스컬레이션을 유발해 복잡한 추론·다중 파일 코딩에서 프론티어 한방이 비용·품질 모두 승리한다.
  - *PEAR* (`arXiv:2510.07505`) · *Planner-as-Router* (`arXiv:2609.32917`) · *RouteLLM* (`lm-sys/RouteLLM`): 강한 플래너·판정자 + 작업 난이도별 하이브리드/경량 실행기 조합이 성능 손실 없이 비용을 절감한다.
