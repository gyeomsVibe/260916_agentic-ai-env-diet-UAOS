### 1.2 1차 학술·시스템 공학 근거
1. **Banich & Belger (1990, *Cortex* 26:77–94; Banich 1998) — 고부하 시 양반구 병렬 처리 이점**:
   - 저부하(`NORMAL`)에서는 단일 반구 처리가 뇌량 전송 비용을 아껴 유리하지만, **고복잡도·고부하(`ELEVATED`/`SURGE`)에서는 좌·우반구에 작업을 분산해 병렬 처리하고 말단에 뇌량으로 통합하는 방식이 반응 속도와 정확도 모두에서 우월**하다.
2. **Blumofe & Leiserson (1999, *JACM* 46(5), MIT Cilk) — Work-Stealing 포크-조인 스케줄러**:
   - $P$개 가동 프로세서에서 작업 훔치기(Work-Stealing)로 직렬 시간 $T_1$을 $\frac{T_1}{P} + O(T_\infty)$로 단축하며 메모리 공간도 $S_1 P$로 억제한다.
3. **Martin Kleppmann (2016, *How to do distributed locking*) — 단조 펜싱 토큰과 배압(Backpressure)**:
   - 단조 증가 `fencing_epoch`를 모든 쓰기·배차 경계에서 검증하면 지연·만료된 구형 총괄 창구의 뒤늦은 지시가 신규 상태를 오염시키는 스플릿 브레인(혼란·꼬임)을 원천 차단한다.

## 2. 좌·우뇌 분산 병렬 급행(Fork) + 말단 고속 순환 교차검증(Join) 4단계 프로토콜

1. **1단계 — 실측 혼잡 감지 (Banich-Belger Crossover)**:
   - `evaluate_congestion_state()`가 대기 카드 `>= 3`, `[긴급]` + 대기 `>= 2`, 최장 대기 `>= 15분`, 총괄 부하 `>= 80%`, 또는 포인터 충돌 `>= 1` 중 하나라도 실측되면 즉시 `SURGE` 모드를 발동한다. 측정값이 누락되면 `UNKNOWN`으로 `fail-closed`한다.
2. **2단계 — 펜싱 에포크 & 비겹침 파일 락 필터 (꼬임·혼란 원천 제거)**:
   - `task.fencing_epoch < active_fencing_epoch`인 구형 창구 지시는 `STALE_OR_MISSING_FENCING_EPOCH`로 즉시 탈락시킨다.
   - 수정 작업인데 `allow_files`가 비어 있으면 `UNSCOPED_ALLOW_FILES_FORBIDDEN`으로 차단한다.
   - `[긴급]` 우선 정렬 후 이미 배정된 카드와 정규화 파일 경로가 1개라도 겹치면 `DISJOINT_FILE_LOCK_CONFLICT`로 다음 웨이브 대기열에 분리하여 `SOURCE_DIVERGED`를 원천 봉쇄한다.
3. **3단계 — 친화성 우선 + Cilk Work-Stealing 병렬 배차 (Fork)**:
   - 각 도구의 고유 해부학 친화성(좌뇌=형식 불변식, 우뇌=거시 맥락, 감각운동=대규모 구현, 로컬 소뇌=`<=20`줄 무판정 조각)에 우선 배정하되, 담당 기관이 이미 웨이브 상한에 도달했으면 **유휴 가동 동료 기관이 즉시 작업을 훔쳐(Work-Steal) 병렬 실행**한다.
4. **4단계 — 말단 1라운드 순환 뇌량 교차검증 (Fast Cyclic Join)**:
   - 모든 병렬 작업이 끝나는 말단에 단일 판정자에게 몰리지 않도록 **3자 순환(`좌뇌→우뇌`, `우뇌→감각운동`, `감각운동→좌뇌`) 또는 2자 미러(`A↔B`)** 로 1라운드에 동시 교차검증한다. `author != judge`는 8개 전 시나리오에서 절대 깨지지 않는다.
