# 모든 프로젝트용 건설적 자율 릴레이

## 왜 바꾸는가

`[DATA] from=antigravity verdict_requested=no`는 상대 도구가 살아 있다는 운송 확인일 뿐이다. 이를 사용자에게 반복 표시하면 작업은 진전되지 않고 사람과 유료 모델의 주의력만 소모한다. UAOS는 이제 "연락 횟수"가 아니라 "검증된 상태 전이"를 진전으로 센다.

## 세 가지 입력 등급

1. `ACK_ONLY`: 생존 확인, `verdict_requested=no`, 이전과 같은 상태, 빈 출력. 수신 시각과 송신자 상태만 내부 기록하고 종료한다.
2. `ACTIONABLE_DELTA`: 새 커밋·diff·PR 댓글, 새 테스트 결과, 검증 실패, P1, 판정 요청, 활성 카드 변경. 다음 실행 단계로 들어간다.
3. `HUMAN_GATE`: 삭제, 원격 push·배포·게시, 결제, 계정·권한·시스템 설정 변경. 준비와 검증은 끝내되 명시 승인 전 실행하지 않는다.

## 30분 실행기의 고정 순서

1. 결정적 검사로 PLAN, 활성 카드, lock, 원격 HEAD, 새 댓글, 사용량 장부를 이전 커서와 비교한다.
2. `ACK_ONLY`뿐이면 Ollama·Claude·Codex·Antigravity를 호출하지 않고 조용히 끝낸다.
3. 실제 변화가 있으면 같은 작업이 완료 또는 진행 중인지 확인한다.
4. 의존성이 충족된 가장 작은 `READY` 작업 하나만 선택한다. 한 주기에 여러 작성자를 열지 않는다.
5. 외부 작업자를 쓸 때는 매뉴얼 전문, 입력 해시, 허용/금지 범위, 예산, 인수 명령, 중단 조건, 독립 판정자를 먼저 전달한다.
6. 결정적 도구로 끝나면 모델을 부르지 않는다. Ollama는 좁은 추출·변환·고정 형식 요약 한 번만 맡는다.
7. 고정 인수 명령, 산출물 존재, diff 범위, 작성자와 검토자 분리를 확인한다. 실패하면 `DONE`으로 바꾸지 않는다.
8. 카드와 장부를 갱신하고, 상대 도구에는 `발견 사실 / 증거 / 요청하는 다음 한 단계`만 보낸다.

## 자율성의 경계

자율성은 더 자주 말하는 기능이 아니라 승인 없이 가능한 다음 작은 단계를 끝내는 능력이다. 반복 상태 신호는 자동 억제하고, 유료 작업자는 실제 판단이 필요하며 계약 예산이 검증된 경우에만 한 번 호출한다. 사용자는 의미 있는 진전, 완료, 실패 또는 `HUMAN_GATE`만 받는다.

## 완료 판정

- `ACK_ONLY` 사용자 메시지 0건
- 같은 상태에서 모델 호출 0건
- 한 주기당 활성 작성 작업 최대 1건
- 각 수행에 고정 인수 결과와 카드 기록 존재
- 실패·P1·승인 필요가 억제되지 않음
- 토큰·시간 절감은 대조 측정 전 `UNMEASURED`
