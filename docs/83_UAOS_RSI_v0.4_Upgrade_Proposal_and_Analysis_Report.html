⚖️ 3대 도구 공동 의사결정: UAOS-RSI 운영체제에 이식할 것인가?
✅ 적극 이식 (Adopt & Integrate) A등급
  • 1. 도구 출력 파일 오프로딩 (maxResultSizeChars): 큰 터미널/테스트 출력을 .work/tmp_output/에 파일로 저장하고 경로만 모델에 넘겨 유료 토큰 폭발을 원천 차단.
  • 2. Haiku 5.5 초경량 계산기 티어 추가: Ollama 0토큰 로컬 모델과 함께, 클라우드 작업 중 단순 반복 수정은 1/10 가격의 Haiku 5.5로 자동 라우팅.
  • 3. CI 기반 지연시간 래칫 관문 (Latency Ratchet): 통신 지연이나 실행 시간이 3배 이상 느려지면 자동으로 릴리스를 차단하는 성능 보호 관문.
  • 4. OpenRig식 선언적 팀 명세 (teams.json): 각 도구의 역할(지휘자, 부지휘자, 감사자, 실행자)을 JSON/YAML 명세로 일원화하여 세션이 바뀌어도 역할 혼선 방지.
⛔ 이식 제외 / 경계 (Reject & Avoid) C등급
  • 1. OpenRig 프레임워크 자체 통째 설치: OpenRig은 macOS/Linux의 tmux 및 별도 백그라운드 데몬에 의존하므로, Windows 11 환경인 사용자 시스템에 충돌을 유발함. (프레임워크 대신 핵심 아이디어만 UAOS 파이썬 코어로 순수 흡수)
  • 2. 외부 클라우드 의존성 강제화: Datadog 등 유료 SaaS 모니터링 연동은 불필요한 비용을 발생시키므로 로컬 SQLite 및 JSONL 장부 유지.
🗓️ UAOS-RSI v0.4 버전업 마스터 스케줄 (3대 도구 합의안)
Stage 1: 토큰 오버플로우 방지 (파일 오프로딩)

도구 실행 출력이 2,000자를 넘길 경우 .work/spill/에 자동 분리 저장하고 요약 및 경로만 전달하여 컨텍스트 낭비 제거.

Stage 2: 1/10 비용의 초경량 티어 (Haiku 5.5 & Ollama) 연동

코드 기계적 슬라이스(20줄 수정, 포맷팅, 단순 테스트 작성)를 고성능 Sonnet 대신 Haiku 5.5 및 로컬 모델로 우선 라우팅.

Stage 3: 선언적 팀 명세 및 데스크 고정 (OpenRig 아이디어 흡수)

.coord/team_rig.json을 도입하여 세션이 갱신되어도 도구별 정체성과 고정 권한(Conductor, Auditor, Merger)이 끊김 없이 유지되도록 설계.

Stage 4: 통신 지연시간 래칫 관문 (CI Latchet Gate)

서신 발행부터 수신까지 p95 2초 이내 반응을 보증하고, 성능 퇴행 발생 시 PR 병합을 자동 차단하는 안전장치 안착.
