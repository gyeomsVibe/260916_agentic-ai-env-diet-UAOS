# 0원 디스크 비동기 통신과 로컬 올라마(Ollama) 전화기 아키텍처

- 상태: `APPROVED-ARCHITECTURE`
- 작성일: 2026-09-24
- 기준: 유료 LLM 상주 폴링(polling) 영구 금지, 0원 디스크 비동기 버스, "올라마 = 전화기" 모델

---

## 1. 핵심 인사이트: "올라마 = 전화기" (The Telephone Model)

### 1-1. 유료 LLM 폴링의 모순: "24시간 켜둔 유료 국제전화"
- 유료 LLM(Codex, Claude Code, Antigravity)이 1분/5분마다 cron으로 깨어나 "할 일 있나?" 상태를 확인하는 것은, 분당 요금이 부과되는 국제전화를 24시간 내내 끊지 않고 연결해 둔 채 침묵을 들으며 돈을 버리는 것과 같다.
- 유료 모델은 **초고가 외부 전문 컨설턴트**다. 자리에 앉혀 두고 잡무를 감시하게 하면 토큰 다이어트는 실패한다.

### 1-2. 올라마의 본질: "대기료 0원의 유선 구내전화 (Intercom)"
- **대기료 0원 (On-hook)**: 수화기를 내려놓고 책상 위에 있을 때 통신비(토큰 요금)는 0원이다. 로컬 GPU VRAM(4.3GB, `keep_alive 30m`)에 상주하므로 대기 비용 없이 항상 대기한다.
- **언제든 즉시 다이얼 (Dial & Speak)**: 지휘자(사용자, Codex, Antigravity)가 원할 때 수화기를 들고 명령(`olla ask`, `olla digest`, `pilot run --worker local`)을 내리면 1.4초 만에 즉시 연결된다.
- **판정 없는 신호 전달 (Transducer)**: 전화기는 수화기를 통해 오가는 음성을 전달할 뿐 스스로 판단하지 않는다. 계산기 원칙과 동일하게 입력 수식과 치환 작업만 기계적으로 수행한다.
- **비상벨 (Wake-on-P1 Ring)**: 평상시에는 침묵하고, 오직 P1 차단 결함이나 사용자 승인 이벤트가 발생할 때만 유료 모델의 전화벨을 1회 울린다.

## 2. 4계층 아키텍처 (4-Layer Telephone Architecture)

```
[지휘자: Codex / Claude / Antigravity]  (유료 모델: 평상시 Deep Sleep, 수화기 내려놓음)
          ▲                                 │
          │ Wake-on-P1 벨소리 (1회 기상)     │ 다이얼 발신 (수화기 들고 0원 작업 지시)
          │                                 ▼
┌─────────┴─────────────────────────────────┴────────────────────────┐
│ Layer 3. 전화벨 제어기 (Ringer / Hook Switch)                       │
│ - P1 차단 결함(인수 실패, 락 충돌) 및 사용자 승인 대기 시에만 1회 호출   │
└─────────────────────────▲──────────────────────────────────────────┘
                          │ 트리거
┌─────────────────────────┴──────────────────────────────────────────┐
│ Layer 2. 구내 교환원 (Resident Sentinel: Local Ollama)              │
│ - 24/7 상주 감시, 상태 점검, 데드락 감시, 무변화 필터링, 60줄 브리핑     │
│ - GPU VRAM 상주 (비용 0원, 30분 keep_alive)                         │
└─────────────────────────▲──────────────────────────────────────────┘
                          │ 디스크 I/O (비용 0원)
┌─────────────────────────┴──────────────────────────────────────────┐
│ Layer 1. 물리 전송선 (Physical Wire: 0-Token Disk Bus)             │
│ - .coord/mailbox/ (inbox, outbox, spool)                           │
│ - .coord/stream/events.jsonl (원자적 append-only 로그)              │
└────────────────────────────────────────────────────────────────────┘
```

### Layer 1: 물리 전송선 (0-Token Disk Bus)
- 통신 매체는 네트워크 API가 아니라 OS 파일 시스템(디스크 I/O)이다.
- `.coord/mailbox/inbox/`: 들어오는 작업 및 이벤트 메시지 스풀.
- `.coord/mailbox/outbox/`: 작업 완료 및 알림 스풀.
- `.coord/stream/events.jsonl`: 전체 조율 흐름의 단일 원자적(atomic) 추가 전용 로그.
- 토큰 소모: **영구히 0 토큰**.

### Layer 2: 구내 교환원 (Resident Sentinel: Local Ollama)
- 로컬 `qwen2.5-coder:7b` 모델이 상주 감시관으로 동작.
- OS 경량 파일 감시(또는 저비용 타이머)로 디스크 버스를 감시.
- 수행 업무:
  1. 잡음 필터링: 정상 처리, 무변경 이벤트는 지휘자에게 전달하지 않고 종결.
  2. 초압축 브리핑: 변경 로그를 60줄 이하의 결정적 텍스트로 요약(`coord/brief.py`).
  3. 교착 감시: 60분 초과 고착 잠금(`QUIET_LOCK`, `database is locked`) 감지.

### Layer 3: 전화벨 제어기 (Wake-on-P1 Ringer)
- 유료 지휘자를 깨우는 관문(Gate).
- **벨이 울리는 조건**:
  - `P1_ACCEPT_FAIL`: 인수 테스트 실패(`acceptance_exit != 0`).
  - `P1_DEADLOCK`: 잠금 충돌 및 타임아웃 발생.
  - `GATE_USER_APPROVAL`: 데이터 삭제, 원격 push, 배포, 결제 등 윤겸스 명시 승인 대상.
- 조건 미충족 시 유료 지휘자는 깨어나지 않으며 토큰 소비 0을 유지.

### Layer 4: 수화기 인터페이스 (Handset: Dial & Speak)
- 지휘자가 올라마를 호출하는 단일 창구:
  - `olla ask "질문" -f <파일>`: 0원 즉시 자문 및 분류.
  - `olla digest -f <파일>`: 대형 파일 3,000토큰 초과 시 사전 줄 번호 압축(-91.8% 토큰 절감).
  - `pilot run --worker local`: SEARCH/REPLACE 기반 단순 반복 수정 작업 위임.

## 3. 운영 원칙

1. **상주 폴링 절대 금지 (Zero Polling Invariant)**:
   - 유료 API 기반 cron/loop 폴링은 즉시 시스템 결함으로 간주한다.
2. **비용 격리 (Cost Isolation)**:
   - 모든 상시 감시 및 메시지 중계는 로컬 올라마와 OS 디스크 버스만 사용한다.
3. **선별 1회 기상 (Single-Turn Wakeup)**:
   - 벨소리를 듣고 깨어난 유료 지휘자는 1턴 안에 결정을 내리고 다시 대기 상태로 복귀한다.
