상태: DESIGN (유지 문서). 작성: Claude(권한대행 부관), 2026-09-28. **Codex 판정 전에는 구현하지 않는다.**
사용자 지시(2026-09-28): ① 절약 모드로 유료 토큰이 얼마나 줄었는지 데이터를 모으고, 오래된 데이터는 자연 소멸시키고, RSI에 연결한다. ② Codex가 한 프로젝트가 끝날 때까지 버티게 한다. ③ Claude Code·Antigravity에도 도구에 맞는 사용 전략을 세운다. ②·③은 Codex와 상의해 확정한다(우편 `relay_840c1ac3`).

표기: **사실**(장부·명령으로 확인), **추론**(사실에서 끌어낸 판단), **미측정**(아직 재지 않음).

## 1. 절약량 측정 (사용자 지시 ①)

### 1-1. 무엇을 "절약"이라고 부를까

유료 모델이 **하지 않은 일**의 토큰은 직접 잴 수 없다. 그래서 두 등급으로 나눈다.

| 등급 | 정의 | 언제 쓰나 |
|---|---|---|
| MEASURED | 같은 작업 종류를 "유료만"과 "로컬 먼저"로 각각 돌린 **통제 쌍(controlled pair)** 의 유료 토큰 차이 | U55 규칙대로 유효 표본 10쌍 이상일 때만 |
| ESTIMATE | 로컬 결과가 관문을 통과한 호출마다, 로컬이 대신 읽은 입력 토큰 − 유료 모델이 그 결과를 읽은 토큰 | 매일 보는 추세. 절약액 주장에는 쓰지 않는다 |

- 왜 ESTIMATE를 로컬 입력 토큰으로 잡나: `local_read_map`이 1,200줄 파일을 지도로 줄이면, 유료 모델은 그 파일 대신 지도만 읽는다. 대신 읽은 양이 곧 덜 쓴 양의 상한이다. 관문에서 떨어진 로컬 결과는 유료 모델이 결국 다시 읽으므로 0으로 센다.
- 전역 규칙: "유료 토큰 0"은 "비용 0"이 아니다. 로컬 토큰·벽시계는 따로 적는다.

### 1-2. 장부에 더할 것

행마다 이미 `work_id`, `worker`, 입력·출력·캐시 토큰, `wall_time_s`가 있다. 새 칸은 하나만 더한다.

- `thrift_route`: `local_first` | `paid_only` | `local_fallback_paid`(로컬 2회 실패 뒤 유료로 한 번 넘김). 없으면 `unknown`.

같은 `work_id`의 유료 행과 로컬 행을 묶으면 작업 하나의 "유료 토큰/로컬 토큰/실패 넘김 수"가 나온다.

### 1-3. 자연 소멸(decay)

두 층으로 나눈다. 판단에 쓰는 가중치는 자동, 파일 삭제는 사람 승인이다.

1. **가중치 소멸(자동)**: `rsi report`가 행마다 무게 `0.5 ^ (나이_일 / 14)`를 곱해 평균을 낸다. 반감기 14일인 이유: 규칙 판(5.23→5.28)과 도구 설정이 약 1주 단위로 바뀌고, 도구 사용량 창이 주 단위로 초기화된다. 14일이면 2주 전 행이 절반, 6주 전 행이 1/8만 반영된다. 10쌍 표본이 모이면 조정한다(**미측정**).
2. **보관 이동(자동, 삭제 아님)**: 90일 넘은 행은 판단에서 빼고, 기존 `rsi retention`의 검증된 압축 보관(`rollup_jsonl`, .gz + 요약)으로 옮기는 **계획서만** 만든다. 90일인 이유: 반감기 14일에서 90일 행의 무게는 약 1.2%로 판단에 거의 영향이 없다.
3. **실제 삭제**: 지금처럼 `--purge --approval <파일>`로만 한다. 사용자가 "90일 넘은 보관본 삭제"를 상시 승인하기 전까지는 사람이 결정한다.

### 1-4. RSI 연결

- `rsi report`에 `thrift` 절을 더한다: 작업 종류별 가중 유료 토큰, 로컬 비율, ESTIMATE, MEASURED 쌍 수.
- `rsi propose` 후보 두 가지:
  - 로컬 먼저 경로가 한 작업 종류에서 가중 통과율 ≥ 0.8이고 표본 ≥ 10이면 → "이 종류는 기본 로컬" 후보.
  - 같은 원인 로컬 실패가 2회 이상이면 → "이 종류는 유료로 되돌림" 후보(전역 규칙: 같은 원인 2회면 경로 변경).
- 후보는 기존 `rsi gate`(장부 재계산)를 거치고, 제안한 도구는 자기 후보를 판정하지 않는다.

## 2. Codex 수명 연장 (사용자 지시 ②, Codex 상의 대기)

목표: 프로젝트 하나를 여는 날부터 닫는 날까지 Codex가 **판정과 계획**을 계속할 수 있게 한다.

1. **Codex는 판정·계획만.** 구현·탐색·테스트 실행은 Claude(pilot apply, 0토큰 받아쓰기)와 Ollama가 한다. Codex는 저장소를 뒤지지 않는다.
2. **판정 한 건 = 새 호출 한 번.** 긴 대화 대신 `codex exec`(stdin은 `< /dev/null`)에 증거 묶음을 넣는다. 묶음은 Claude가 만든다: 카드 ID, diff 요약, 인수 명령과 종료 코드, 반례 결과, 입력 해시. 상한 20,000 입력 토큰(측정한 짧은 호출 13,109의 약 1.5배 여유).
3. **판정은 모아서.** REVIEW 카드를 PR마다 따로 묻지 않고 하루 1~2회 묶어서 묻는다.
4. **대화형 Codex 세션은 카드가 닫힐 때마다 새로 연다.** 상태는 PLAN·카드·인계 묶음(U56)에 두고 대화 기록에 두지 않는다.
5. **마지막 판정 몫을 남긴다.** U56 절약 모드(표시 잔량 20% 미만) 진입 시 프로젝트 마감 판정 1건 분량을 예약한다.
6. **측정**: `coord usage-session`으로 "닫힌 카드당 Codex 토큰"을 잰다. 10카드가 모이기 전에는 효과를 **미측정**으로 둔다.

## 3. 도구별 사용 전략 (사용자 지시 ③, Codex 상의 대기)

| 도구 | 강점(사실·추론) | 맡길 일 | 맡기지 않을 일 |
|---|---|---|---|
| Codex | 저장소 지휘자, 판정 이력 | 계획·순서, 최종 판정, 재검토 | 탐색, 구현, 긴 대화, 대기 폴링 |
| Claude Code | 긴 문맥·도구 연동, 이 PC에서 가장 자주 ACTIVE | 구현(pilot apply), 증거 묶음 작성, 부재 시 권한대행 | 자기 결과의 단독 판정, 하위 에이전트 남발(찬 시작마다 문맥 재구성) |
| Antigravity | 다른 회사 모델, 웹·브라우저 | 웹·GitHub 조사, 독립 반례 검토(다른 모델이라 독립성) | 구현, ACTIVE가 아닐 때 호출(09-26부터 LIMITED) |
| Ollama | 유료 토큰 0, 로컬 | 파일 지도, 요약, 추출, 초안, 커밋 메시지 | 설계, 승인, 판정 |

- Antigravity pilot 1회 평균 입력 약 113,000토큰(3,057,566 ÷ 27, 사실). 조사 질문 하나에 한 번만 부르고 결과는 파일로만 받는다.
- Claude 세션은 캐시 읽기가 대부분이다(60,818,998, 사실). 단계가 바뀌면 새 세션으로 시작하고 결정은 PLAN에 남긴다.
