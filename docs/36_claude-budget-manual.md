# Claude Code 토큰예산절약 모드

상태: 유지(maintained). 권위: `docs/27_token-budget-routing-policy.md`와 `.coord/PLAN.md`. 이 문서는 Claude Code가 현재 프로젝트에서 바로 적용할 실행 절차다.

1. 작업 카드의 ID·단일 작성자·허용 파일·인수 명령을 확인한다. Codex가 활동 중이면 Claude는 지정된 구현 또는 독립 검토만 맡는다. Codex가 실제로 제한·부재일 때에만 부지휘자로 단일 계획을 대행한다.
2. 작업 시작과 끝에 `/usage`의 구독 사용량 막대·재설정 시각을 기록한다. 세션 입력·출력·캐시 토큰은 별도 열로 둔다. `/context`로 문맥 팽창을 확인한다. 계정 수치를 얻지 못하면 `UNKNOWN`이고 자동 승계 근거가 아니다.
3. 예상 종료 잔여율과 예약량은 `docs/27` §3으로 계산한다. 표본 부족이면 새 장문 조사 대신 좁은 카드 1개만 선택한다. 사용량이 낮아도 중요 구현·검토를 수행할 예약량이 없으면 새 유료 단계를 열지 않는다.
4. 파일 찾기·줄 지도·로그 분류·형식 변환은 `rg`/결정적 스크립트 또는 `olla`로 먼저 처리한다. Ollama에 판단을 묻지 않는다. 입력 파일 해시와 추출 규칙을 정하고 원문 구간을 다시 열어 확인한다.
5. 큰 결과를 현재 대화에 통째로 넣지 않는다. 관련 파일·줄 범위만 읽고, 인계는 작업 ID·변경 파일·인수 명령/exit·위험·다음 소유자만 담는다. 서로 무관한 과제로 넘어갈 때는 새 세션을 열고 카드로 문맥을 옮긴다. 같은 과제의 긴 대화는 `/compact`로 필요한 증거만 남긴다.
6. 모델 선택은 작업 난도에 맞춘다. 모호한 아키텍처·보안 판단은 강한 모델에 남기고 기계적인 부분은 Ollama에 보낸다. 모델·추론 설정 변경은 실제 사용량을 다시 측정한다. 외부 작업자나 하위 에이전트는 각각 별도 문맥과 사용량이 있으므로 무조건 병렬화하지 않는다.
7. 구현 후에는 고정 인수·숨은 반례·diff·원본 해시를 확인한다. Claude가 작성자라면 Antigravity 또는 Codex의 독립 검증을 요구하고 자기 PASS만으로 `DONE` 처리하지 않는다. Codex 복귀 시 변경과 판정 근거를 재검토 목록에 남긴다.
8. Claude 한도 초과 시 비동기 카드만 디스크에 남기고 유료 모델의 주기적 폴링을 시작하지 않는다. Codex가 가용하면 총괄을 반환한다. Codex도 제한·부재인 경우에만 Antigravity가 임시 대행한다.

공식 근거: [Claude Code 비용·사용량·문맥 관리](https://code.claude.com/docs/en/costs), [CLAUDE.md·스킬·훅의 문맥 비용](https://code.claude.com/docs/en/features-overview). 구독 한도 감소를 세션의 추정 달러 비용과 동일시하지 않는다.

RSI 인계: 각 작업의 `/usage` 전후 상태와 로컬·원격 호출 영수증을 같은 `work_id`로 [장부](../.coord/usage/README.md)에 남긴다. [RSI 정본](31_evidence-gated-rsi-for-uaos.md)에 따라 개선 제안을 낼 수 있지만 자기 작성 변경은 독립 판정 전 `REVIEW`다.
