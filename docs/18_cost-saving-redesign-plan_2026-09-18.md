두 도구에는 위 증거를 요약 제공했고 도구 실행·파일 수정 없이 설계 의견만 요청했다. 독립 코드 감사로 표현하지 않는다.

- Claude Code: print/plan, 도구 비활성화, session `857c2342-1311-4a3f-a041-0998565a0475`, exit 0, 1턴, 약 53.7초. 보고된 API 환산 cost USD 0.141583(실제 구독 청구액이라는 뜻 아님). INVALID 분리, 타임아웃 포함 종료 상태, 반복 실험, 캐시·출력 비용 분리 권고.
- 공통 채택: 측정 오류를 먼저 수정하고, LLM 상태 확인 루프 제거, 제한된 입력, 테스트·diff에 기반한 검토, 실패 비용 보존.
- 보류/수정: 폴링·컨텍스트 과적재가 P05의 직접 원인이라는 의견은 가설이다. 확인된 직접 오류는 실행 환경 초기화 실패다. 각 경로의 비용/품질 서열도 미측정이다.
- 테스트 개수 증가나 tool_events>0만으로 PASS를 결정하지 않는다. 이벤트 형식에 따른 누락이 가능하고 무의미한 테스트도 추가할 수 있다. 요구 기능을 검증하는 독립 고정 테스트와 산출물 해시가 필요하다.
- 매번 작업 폴더 삭제 제안은 채택하지 않는다. 새 run ID와 별도 작업 사본을 사용하고 보존한다. SQLite 쓰기는 기존 단일 writer만 소유한다.

## 4. 권고 구조: 기존 pilot 재사용 + 작은 실행 제어층

사용자 요청 → Codex의 짧은 작업 계약 → 일반 프로그램이 pilot 1회 실행 → Antigravity 단일 워커 → 고정 인수 테스트·diff·원장 검사 → Codex 증거 검토 1회 → 기존 승인 범위 안에서 bundle 반영.

- Codex는 과제 정의와 최종 판정 담당. 계획 비용도 측정에 포함한다. 정상 경로 최대 2개 논리 호출(계약 작성, 검토), 실행 중 상태 질의 0회 목표. 실제 내부 모델 호출 수·토큰은 별도로 수집한다.
- 상태 대기·timeout·process exit·원장 기록·원자 summary 저장은 프로그램 담당. 기존 broker/lease/reconcile을 재사용하며 새 데몬·분산 큐를 만들지 않는다.
- 구현은 Antigravity의 기존 SQLite pilot 경로만 사용한다. Claude는 설계·측정 검토 때만 읽기 전용 참여하며 모든 과제의 상시 검토자로 추가하지 않는다.
- 완료 이벤트에는 run ID, attempt ID, 상태, summary 경로·해시를 붙인다. 누락/중복/지연 이벤트는 멱등 소비하고 프로세스 종료 후 제한 시간 안에 원장을 확인한다. 복구용 저빈도 프로그램 확인은 허용하되 LLM을 호출하지 않는다.
- 컨텍스트는 목표, 허용 파일, 필요한 소스, 고정 테스트 계약만 전달한다. 초기 목표는 작업 패킷 8k 토큰, 검토 패킷 4k 토큰. 이는 총 모델 입력 상한이 아니다. 필요한 diff가 넘치면 누락 승인하지 않고 검토 범위를 확대하며 비용에 기록한다.
- 과거 대화·전체 로그·전체 도구 설명을 반복 전달하지 않는다. 프로젝트 규칙과 안전 규칙은 유지한다. 범위 축소가 규칙 무시를 의미하지 않는다.
- 같은 원인 재시도 0회, 새 증거와 수정된 원인이 있을 때만 새 attempt. TIMEOUT/UNKNOWN effect는 reconcile 전 재실행 금지. 쿼터 소진은 명시적 BLOCKED, 무한 모델 폴백 금지.
- 감시·staging·원본 해시·허용 파일·승인 bundle 계약은 유지한다. 감시 밖 쓰기 보증 불가도 유지한다. 성능 개선 목적으로 감시를 조용히 제외하지 않는다.

## 7. 측정 계약과 채택 기준

1. 모든 실행은 같은 baseline 콘텐츠 해시, 목표, 고정 외부 인수 테스트, 자원 제한을 사용한다. 테스트는 원본 샘플에서 실패하고 정답 fixture에서 통과해야 한다. 워커는 이 평가 테스트를 수정할 수 없다. 요구 테스트 추가도 별도 확인한다.
2. 고정 model ID·effort·CLI 버전·규칙/도구 설정 해시를 기록한다. Codex 측 조건은 A/B에서 동일, agy 모델은 모든 B에서 고정한다. 서로 다른 실행자의 비교는 시스템 비교이며 동일 모델 추론 비교라고 부르지 않는다.
3. summary 존재뿐 아니라 run/attempt/source/bundle 해시와 원장 terminal state가 일치해야 한다. 승인 반영 평가에는 실제 APPLIED와 반영 후 고정 테스트가 필요하다. 프로세스 exit 0만으로 성공 처리하지 않는다.
4. PASS, TASK_FAIL, INVALID_SETUP, BLOCKED_POLICY, TIMEOUT_UNKNOWN, INVALID_MEASUREMENT를 구분한다. 안전 차단은 정상 제어 결과지만 작업 성공은 아니다. 모델 평가에서 INVALID는 분리하고, 운영 비용/시간에는 실패 시도까지 모두 포함한다.
5. 실행 순서는 교차·무작위화하고 매번 새 샘플을 만든다. 같은 PC에서 다른 AI 작업과 측정 시간을 겹치지 않는다. 실험은 최소 3과제×3쌍, 결과 분산이 크거나 한계선이면 최대 5쌍으로 확대한다. 작은 표본의 p95를 일반화하지 않는다.
6. 전체 입력, 캐시 입력, 비캐시 입력, 출력, 모델별 환산액, 실제 제공되는 구독 사용률, 경과 시간, 승인/수동개입, 재작업/실패 비용을 별도 기록한다. 구독 5시간 창은 계정 공유·해상도·리셋 때문에 정확한 과제 비용으로 단정하지 않는다. 미제공/다른 작업 오염이면 UNKNOWN이다.
7. 총비용은 계약 작성+워커+검토+재작업+실패 비용이다. 정가 환산액과 실제 청구액/구독 할당량을 구분한다. 개발비·설계비는 일회성 비용으로 별도 표시하고, 절감액이 양수일 때만 손익분기 과제 수를 계산한다.
8. 제안 채택 게이트: 고정 품질 시험 전부 통과, 새 blocking P1 0, 거짓 PASS 0, 중형 과제 Codex 비캐시 입력+출력 중앙값 50% 이상 감소(대리지표), 전체 환산 비용 20% 이상 감소, 완료 시간 중앙값 A의 1.25배 이하. 이는 목표값이며 달성 주장이 아니다. 가격/사용량 자료 부족 시 비용 게이트는 UNMEASURED로 남긴다.
9. 소형 작업은 위임 비용이 더 크면 A로 라우팅한다. 2쌍 연속 품질 미달 또는 비용/시간 우위 가능성이 없으면 확대 실험을 중단하고 증거만 보존한다. 전체 사용 예산은 실행 전 수치로 고정한다. 이번 설계 검토는 새 구독·API 결제·전역 배포를 요구하지 않는다.

## 8. 완료 정의와 다음 한 단계

이 계획의 연구·협의는 완료다. 비용절감은 UNMEASURED이며 운영 기본값은 아직 변경하지 않는다.
다음 구현의 첫 단계는 R0: P05 INVALID 정정 기록과 측정기 거짓 PASS 차단이다. 그 다음 정상 실행 가능한 B0를 확인한 뒤 B1의 최소 변경만 착수한다.
M4의 기존 FAIL/STOP 판정은 역사 기록으로 보존하고, 후속 카드에 이 문서의 정정 근거를 연결한다. 기존 측정 JSON을 덮어써 과거 기록을 지우지 않는다.
