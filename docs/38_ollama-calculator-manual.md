# Ollama 전자계산기·전화기 작업명령 매뉴얼

상태: 유지(maintained). 권위: `docs/27_token-budget-routing-policy.md`. 사용자 정의: **Ollama = 단순 추론·의지 없는 전자계산기, 필요할 때 호출하는 전화기**.

## 호출 전 계약

지휘 도구가 다음 칸을 모두 채운다. 빈칸이나 모호한 목표는 모델로 넘기지 않고 지휘 도구가 좁힌다.

```text
work_id: Uxx-작은단계
operation: 한 문장으로 정한 추출/변환/정확한 치환 1개
input: 허용 파일의 정확한 경로와 SHA-256
output: 허용 경로·형식·최대 길이
edit: 정확한 SEARCH/REPLACE 1회 또는 결정적 추출 규칙
forbidden: 비밀 읽기·원격 전송·범위 밖 쓰기·설계/판정/승인
timeout: 작업 카드에서 정한 상한
acceptance: 결정적 명령과 기대 exit 0, 원본/후보 diff 검사
stop: 출력 없음·형식 실패·해시 불일치·인수 실패면 중단
```

구체성 80점은 현재 프로젝트의 입력 완전성 문턱이다. 80점 이상이라도 모델은 오류를 낼 수 있다. 성공은 인수 명령과 독립 원본 비교로만 결정한다. `olla ask -f <파일>`은 읽기·초안, 원본 수정은 격리된 `pilot run --worker local`로 처리한다. 로컬 서버가 없으면 실패를 그대로 기록하고 원격으로 몰래 승격하지 않는다.

## 호출 후 영수증

- `work_id`, 호출자(Codex/Claude/Antigravity), 모델, 시작/종료 시각, 입력·출력 로컬 토큰, 벽시계, 프롬프트 해시, 파일 해시, 종료코드, 인수 결과를 기록한다. 원문 프롬프트나 비밀은 사용량 장부에 복사하지 않는다.
- 지휘 도구는 결과의 원문 대조·diff·숨은 반례를 직접 확인한다. 모델이 “완료”라고 적어도 출력·실제 변경·인수가 없으면 실패다.
- 같은 작업의 재시도는 원인 분류 후 한 번만 한다. 성공률과 시간은 작업 유형별 10건 단위로 분석해 명령서의 구체성, 출력 상한, 모델 선택을 갱신한다. 유료 계정 절감은 별도 A/B 전후 한도 비교가 없으면 `UNMEASURED`다.

## 실측에서 배운 제한

- U23 문서의 7단계는 로컬 20,434 입력·7,700 출력 토큰과 315.9초를 기록했지만, 후속 독립 반례에서 복구 ID 손상과 감시관 알림 충돌이 나왔다. 로컬 PASS가 완성품 품질을 보증하지 않는다.
- U21~U22의 더 모호한 과제에서는 로컬 실패 뒤 Antigravity 호출이 커져 오히려 비용이 늘었다. 좁은 파일·정확한 치환·숨은 인수로 계약을 작게 만들고, 실패하면 지휘 도구가 경로를 다시 선택한다.
- Ollama는 24시간 판단하는 주체가 아니다. OS 감시 루프는 결정적 규칙으로 이벤트를 찾고 필요할 때만 Ollama에 한정된 계산을 요청한다. 디스크 우편함을 실제로 무손실이라고 부르기 전에는 U23 재작업 인수를 통과해야 한다.

RSI 사용 기록: 호출자는 `prompt_eval_count`/`eval_count`/벽시계·실패를 같은 `work_id`의 [장부](../.coord/usage/README.md)에 기록한다. 기록의 추출·서식 변환은 Ollama에 시킬 수 있으나 [RSI 정본](31_evidence-gated-rsi-for-uaos.md)의 가설 채택·성공 판정은 시키지 않는다. U27 자동 수집 전에는 수동 기록이다.
