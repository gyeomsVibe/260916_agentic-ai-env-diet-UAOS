# 네 AI 도구의 아이디어 조사와 위임 전 매뉴얼 규칙

상태: UAOS 프로젝트 운영 정본, 2026-09-25. 대상: Codex·Claude Code·Antigravity·Ollama. 실제 전역 장착 여부는 문서 존재가 아니라 각 도구의 활성 전역 규칙을 별도 확인한다. 기존 [통합 계획](../.coord/PLAN.md), [예산 규칙](27_token-budget-routing-policy.md), [RSI 규칙](31_evidence-gated-rsi-for-uaos.md)과 함께 읽는다.

## 사용자의 원자료에서 실행 계약까지

사용자는 완성된 기술 명세를 쓸 의무가 없다. 네 도구는 가공되지 않은 개념에서 **목표·모르는 전제·위험·성공 기준**을 찾아내고, 공개 근거와 현재 프로젝트 증거를 대조해 실행 가능한 작은 계약으로 만든다.

1. 사용자 문장을 “확인된 사실 / 바라는 결과 / 아직 검증되지 않은 가정”으로 나눈다. 사실이 불분명해도 안전한 읽기·조사는 계속한다.
2. 최신성이 중요하거나 링크·정확한 출처가 필요한 주장에는 웹을 확인한다. GitHub는 실제 구현·이슈, 공식 문서는 지원 계약, 논문은 연구 가설·실험, Reddit은 실패 사례와 현장 의견으로 취급한다. 출처·날짜·대상 환경을 남기고 서로 다른 증거의 무게를 혼동하지 않는다.
3. 결과를 파일·작업 카드·결정적 검사로 표현한다. 단순 출력의 길이는 사용자에게 짧게, 저장소의 학습 설명은 처음 보는 사람에게 필요한 만큼 충분히 쓴다.
4. 바뀐 규칙·코드에는 반례와 독립 검증자를 둔다. 실패·고비용 호출도 [사용량 장부](../.coord/usage/README.md)에 남기고 RSI의 분모에서 숨기지 않는다.

## 안티그래비티·올라마 호출 전 필수 발행

Codex·Claude Code·Antigravity 중 누가 호출하든 **작업 프로세스 매뉴얼을 호출 전에 파일로 발행하고, 해당 호출의 입력으로 전달**한다. 매뉴얼에는 작업 ID, 한 목표, 입력 경로와 해시, 허용 출력·수정 파일, 금지 행동, 비용·시간 상한, 검사 명령, 실패 시 중지 조건, 최종 판정자를 적는다. 이미 같은 계약의 최신 매뉴얼이 있으면 중복 발행 없이 그 파일의 해시와 전달 사실을 기록한다.

Ollama는 **생각 없는 전자계산기이자 필요할 때 쓰는 유선 전화기**다. 호출자는 해답을 계산하도록 좁은 지시를 내리고, 결과를 외부 증거와 검사로 판단한다. Ollama에게 목표·설계·권한·합격·다음 작업 선택을 맡기지 않는다. 로컬 사용은 유료 API 토큰 0일 수 있지만 컴퓨터 자원 비용과 실제 계정 절감률은 따로 잰다.

Antigravity는 비용이 드는 원격 작업자다. 같은 일을 Codex·Claude·Antigravity에 중복 발주하지 않는다. 특히 간단한 추출·변환은 Ollama로 먼저 시도한다. 설계 판단이나 로컬 실패 후 승격할 때는 새 계약의 허용 파일과 비용 한도를 고정하고, 작성자와 다른 도구가 diff·인수를 검토한다.

## 두 가지 작업명령 예시(few-shot)

**예시 A: 정확한 추출**

> 사용자: “지난 작업에서 계정 사용량을 얼마나 아꼈어?”
>
> 매뉴얼: “입력은 U27 영수증 하나. 로컬 입력·출력 토큰, 원격 입력·출력 토큰, 계정 사용량 전후값을 각각 추출. 없는 값은 `UNKNOWN`. 출력 8줄. 파일 수정 금지.”
>
> 검사: 지휘자가 원본 숫자를 대조한다. 계정 전후값이 없으면 계정 절감률은 `UNMEASURED`.

**예시 B: 설계 질문**

> 사용자: “AI가 알아서 더 나아지게 해줘.”
>
> 매뉴얼: “Antigravity는 기존 RSI 규칙과 실패 사례만 읽고, 개선 가설 2개·각 반례 1개·비용 상한을 제안. 파일 수정 금지. Codex가 채택 여부를 판단.”
>
> 검사: 단독 자기 점수로 기존 규칙을 변경하지 않는다. 다음 구현 단계에는 별도 고정 인수를 만든다.

## 자료 근거와 한계

- [OpenAI Docs: 에이전트 평가](https://developers.openai.com/api/docs/guides/agent-evals)는 도구 선택·인계와 실행 흔적을 평가하라고 설명한다. UAOS에서는 이를 파일럿 원장·독립 인수로 구체화한다.
- [OpenAI Docs: 평가 설계](https://developers.openai.com/api/docs/guides/evaluation-best-practices)는 목표·데이터·지표·비교를 분리한다. UAOS에서 측정되지 않은 절감을 `UNMEASURED`로 두는 이유다.
- [GitHub README 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)는 첫 방문자가 시작 경로를 찾도록 설명한다. UAOS는 짧은 README와 상세 학습 가이드를 연결한다.
- [Ollama 응답 API](https://docs.ollama.com/api/generate)의 토큰 필드는 로컬 연산량 자료다. 유료 계정 절감액을 직접 증명하지 않는다.
- [Self-Refine 논문](https://arxiv.org/abs/2303.17651)은 반복 수정 가능성을 보여 주지만, 이 프로젝트의 무인 자기 변경 허가는 아니다.
- [Reddit 로컬 코딩 경험담](https://www.reddit.com/r/LocalLLaMA/comments/1vq128f/making_small_local_models_actually_useful_for/)은 작은 작업·격리 검사의 실무 아이디어를 준다. 그 글의 성능 수치는 UAOS의 실측치가 아니다.

전역 배포는 Codex·Antigravity의 생성본이 아니라 영문 규칙 정본, Claude의 전역 규칙, 도구 호출자의 실제 입력 계약까지 대조해야 한다. 프로젝트 규칙만 추가했다면 다른 프로젝트에도 적용된다고 주장하지 않는다.
