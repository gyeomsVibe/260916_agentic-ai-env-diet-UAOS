## 1. 아키텍처 선언 배경 및 사용자 최고 의지

### 1.1. 상주 모니터링의 모순과 토큰 낭비 근절
AI 환경 다이어트의 핵심 목표는 **유료 API 토큰 소비 최소화 및 계정 한도 보존**이다. 그러나 기존의 15분 주기 유료 LLM 상주 폴링(Cron) 방식은 다음과 같은 치명적 모순을 내포하고 있었다:
- **대화 컨텍스트 누적 재전송**: 15분마다 단순히 "변동 사항 없음" 1줄을 확인하기 위해 수만~수십만 토큰에 달하는 대화 이력과 시스템 프롬프트를 매번 클라우드 API로 전송.
- **프롬프트 캐시 만료**: 15분 간격은 5분 캐시 TTL(Time-To-Live)을 초과하므로 매 호출마다 100% 유료 과금 발생.
- **무의미한 계정 한도 증발**: 하루 96회 무변동 폴링만으로도 일일 수백만 토큰의 한도가 조용히 소진되어 정작 중요한 개발·설계 작업 시 `QUOTA_EXHAUSTED`로 멈추는 사태 초래.

### 1.2. 사용자 확정 지시 (User Mandate)
> **"토큰 소비가 0원인 디스크 파일 기반 비동기 통신과 로컬 올라마(Ollama) 상주 감시관(Sentinel) 아키텍처를 3대 도구 전체에 공론화해서 이 방향으로 완전히 전환하라. 이것이 사용자의 확고한 의지이다."**

이에 따라, 3대 도구(Codex, Claude Code, Antigravity)는 유료 API를 통한 직접 상주 모니터링을 전면 금지하고, **비용 0원의 디스크 파일 기반 비동기 큐/스풀**과 **로컬 GPU 기반 올라마 상주 감시관**을 단일 표준 통신 및 감시 계층으로 공식 확정한다.

## 2. 글로벌 선행 연구 및 오픈소스/커뮤니티 심층 근거 (Deep Research Dossier)

본 아키텍처는 독자적인 임시방편이 아니며, 최신 AI 다중 에이전트 학술 논문, GitHub 주요 오픈소스 프로젝트, 그리고 Reddit(r/LocalLLaMA) 실전 엔지니어링 커뮤니티가 도달한 공통 컨센서스와 정확히 일치한다.

### 2.1. 학술 논문 및 최신 연구 (arXiv / Conferences)

1. **`tap` (arXiv:2606.14445): Heterogeneous LLM Collaboration over Shared Codebase**
   - **핵심 요약**: 서로 다른 벤더의 LLM 에이전트(예: Anthropic Claude와 OpenAI Codex)가 단일 코드베이스에서 협업할 때, 중앙 통신 서버 대신 **Git 워크트리와 파일 시스템(마크다운/메타데이터) 기반 메시지 영속성**을 사용하는 프로토콜 제안.
   - **본 프로젝트 부합성**: 네트워크 브로커나 유료 API 중계 없이 디스크 파일 시스템을 단일 원본(Single Source of Truth)으로 삼아 이종 도구 간 안전한 비동기 인계를 증명.
2. **`FrugalGPT` (arXiv:2305.05176, Stanford University - Chen et al.)**
   - **핵심 요약**: 비용 절감을 위한 "LLM 캐스케이딩(Cascading)" 전략. 비용이 저렴하거나 무료인 로컬 모델을 먼저 실행하여 판정하고, 복잡한 태스크에 한해서만 고비용 상위 모델로 에스컬레이션함으로써 **최대 98%의 API 비용을 절감**하면서도 GPT-4급 품질을 달성.
   - **본 프로젝트 부합성**: 비용 0원인 로컬 올라마를 1차 감시/트리아지로 두고, P1 차단 결함 발생 시에만 유료 지휘자를 깨우는 본 아키텍처의 이론적 토대.
3. **`RouteLLM` (arXiv:2406.18665, LMSYS Org)**
   - **핵심 요약**: 선호도 데이터를 기반으로 강력한 모델(고비용)과 가벼운 모델(저비용) 간 쿼리를 지능적으로 라우팅하여 품질 손실 없이 2배 이상의 비용 절감을 실증.
4. **`Hybrid LLM: Cost-Efficient and Quality-Aware Query Routing` (ICLR 2024 / arXiv:2404.14618)**
   - **핵심 요약**: Edge/Local 디바이스의 온디바이스 모델을 1차 게이트키퍼로 배치하고, 불확실성이 높거나 고차원 추론이 필요한 경우에만 클라우드 모델로 폴백하는 하이브리드 아키텍처.
5. **`LbMAS: Blackboard LLM Multi-Agent System` (arXiv)**
   - **핵심 요약**: 블랙보드 아키텍처에서 발생하는 토큰 폭증 문제를 해결하기 위해, 에이전트가 공유 보드의 전체 내용을 무차별 수신하는 대신 **정리자(Cleaner/Pruning Agent)**와 **통제 유닛(Control Unit)**을 두어 컨텍스트를 압축하고 호출 빈도를 제어해야 함을 규명.

4. **`bMAS` / `Flock` / `agent-blackboard` / `blackboard-core`**
   - 분산 에이전트들이 공용 파일/저장소를 '블랙보드'로 삼아 상태를 공유하고, 불필요한 API 질의를 차단하는 검증된 패턴.

### 2.3. Reddit (r/LocalLLaMA & r/MachineLearning) 실전 엔지니어링 컨센서스

- **"하이브리드 스택(The Hybrid Stack)이 유일한 답이다"**:
  - 커뮤니티 엔지니어들의 일치된 의견: 유료 상용 모델(Claude 3.7/Opus, GPT-4o, Codex)로 24시간 폴링 루프를 돌리는 것은 명백한 "자원 낭비(Token Bleed)".
  - 로컬 모델(Ollama)이 게이트키퍼(Gatekeeper)로서 단순 분류, 서식 검증, 문법 체크, 정기 헬스체크를 0원에 전담하고, 지휘자 모델은 오직 "승인"과 "심층 코드 설계"에만 단발성으로 집중해야 함.
- **토큰 블로트(Token Bloat) 원천 방어**:
  - 에이전트가 실패 루프에 빠져 API 호출을 연발할 때, 로컬 감시관이 이를 파일 레벨에서 즉시 차단(Circuit Breaker)함으로써 계정 파산을 방지.
- **24/7 상주 데몬 안정성**:
  - Ollama는 `systemd` 또는 Windows 백그라운드 서비스로 24시간 무중단 상주가 가능하며, 대기 상태에서는 GPU VRAM만 점유하고 연산 자원 소비는 0에 수렴.

## 3. 비용 0원 디스크 파일 기반 비동기 통신 (Disk Async IPC) 상세 설계

디스크 I/O는 운영체제 커널의 순수 파일 시스템 연산이므로 **유료 API 토큰 소비가 물리적으로 0원**이다.

### 3.1. 통신 디렉터리 구조 (Maildir/Spool Pattern)

```
.coord/
├── mailbox/                  # 비용 0원 비동기 우편함
│   ├── inbox/                # 수신 대기 중인 메시지 (도구별 서브폴더)
│   │   ├── codex/
│   │   ├── claude/
│   │   └── antigravity/
│   ├── processing/           # 현재 작업자가 읽어 처리 중인 메시지
│   ├── archive/              # 완료된 메시지 (감사 추적용)
│   └── dead_letter/          # 파싱 불가 또는 기한 초과 메시지
├── stream/                   # 단일 원본 추가 전용(Append-only) 이벤트 로그
│   └── <YYYYMMDD>.jsonl
├── PLAN.md                   # 전체 마스터 조율 상태 단일 원본
└── notes/                    # 비간섭 보조 메모
```

### 3.2. 메시지 원자성(Atomicity) 및 경합 방지 불변식
1. **임시 파일 작성 후 원자적 이동**:
   - 송신 도구는 `.coord/mailbox/tmp/<uuid>.json`에 메시지를 작성한 뒤, OS 수준의 `atomic rename`(`os.replace`)을 통해 수신자의 `inbox/`로 이동한다.
   - 이를 통해 수신 도구가 작성 도중의 불완전한 조각을 읽는 레이스 컨디션(Race Condition)을 100% 방지한다.
2. **파일 잠금(File Locking) 기반 동시성 제어**:
   - 스트림 로그(`.coord/stream/<YYYYMMDD>.jsonl`) 기록 시 `msvcrt.locking` 또는 단일 잠금 래퍼(`LockFileEx`)를 사용하여 Windows 동시 append 손실을 원천 차단한다.
3. **무의미한 중복 배달 차단 (Deduplication Cursor)**:
   - 각 메시지는 고유 SHA-256 해시를 가지며, 수신 도구는 로컬 커서 파일(`.coord/mailbox/.cursor`)에 처리 완료된 해시를 기록하여 중복 처리를 방지한다.

## 4. 로컬 올라마 상주 감시관 (Ollama Sentinel) 상세 설계

올라마는 로컬 GPU/CPU를 활용하므로 하루에 1만 번을 호출하더라도 **비용 0원**이다.

```
+-------------------------------------------------------------------------+
|                      [로컬 디스크 파일 시스템]                            |
|  .coord/stream/*.jsonl | .coord/PLAN.md | .work/QUIET_LOCK | git status  |
+-------------------------------------------------------------------------+
                                    ▲
                   (OS 파일 변경 감지: 0원 / 0토큰)
                                    ▼
+-------------------------------------------------------------------------+
|          [로컬 올라마 상주 감시관 (Ollama Sentinel Daemon)]              |
|                     (기본 모델: qwen2.5-coder:7b)                        |
|                                                                         |
|  [역할 1] 24/7 상태 감시: 스트림 로그, 잠금 고착, Git 이상 유무 점검       |
|  [역할 2] 로그 트리아지: INFO/P2(자체 정리) vs P1/차단(지휘자 소환) 분류  |
|  [역할 3] 제로토큰 압축: 수천 줄 로그 -> 60줄 정밀 브리핑 (olla digest)  |
|  [역할 4] 게이트키퍼: 평상시 유료 모델 완전 동면, 중대 사건 시만 1회 기상 |
+-------------------------------------------------------------------------+
                                    │
                       (P1 발생 시에만 신호 파일 작성)
                                    ▼
+-------------------------------------------------------------------------+
|                       [3대 유료 지휘 도구]                              |
|           Codex  |  Claude Code  |  Antigravity                         |
|   (평상시: 동면 / 신호 수신 시: 60줄 압축 브리핑 1턴 섭취 후 즉시 판정)   |
+-------------------------------------------------------------------------+
```

### 4.1. 올라마 감시관의 4대 핵심 임무
1. **무제한 24/7 헬스체크 및 데드락 감시 (Triage: 비용 0원)**:
   - `.work/QUIET_LOCK`이 60분 이상 방치된 고착 상태인지 주기적으로 점검.
   - 하네스 프로세스 충돌(Crash), 미정리 원장(`NEEDS_RECONCILIATION`), 인수 테스트 실패 로그를 실시간 분석하여 `CODE` vs `INFRA` 오류를 0원으로 사전 분류.
2. **초압축 브리핑 생성 (Zero-Cost Briefing)**:
   - 유료 모델이 방대한 로그를 직접 읽으면 수만 토큰이 소모된다. 올라마가 `olla digest`를 통해 변동 사항을 60줄/6KB 이하의 핵심 요약(`codex_brief.md`)으로 압축.
3. **유료 지휘자 기상 게이트키퍼 (Wake-on-P1 Gatekeeper)**:
   - 정상 진행 중이거나 단순 변경(INFO)일 때는 유료 모델(Codex, Claude Code, Antigravity)을 절대 깨우지 않는다.
   - **사용자 승인이 필요한 안전 경계(삭제, 푸시, 배포, 결제, 권한)** 또는 **인수 차단(BLOCKED P1)** 상황이 발생했을 때만 유료 도구의 `inbox`에 기상 신호(Wake Signal)를 투입.
4. **단순 노가다 코드/테스트 스텁 초안 작성 (Calculator Work)**:
   - 계산기 원칙에 따라 반복적인 마이그레이션, 테스트 틀, 서식 변환은 올라마가 무비용으로 선작성(`pilot run --worker local`).

## 5. 3대 도구(Codex, Claude Code, Antigravity) 통합 수용 및 공론화 규칙

### 5.1. 도구별 고정 준수 사항

| 도구 | 기존 비효율 (금지 대상) | 새 표준 준수 사항 (0원 아키텍처) |
| :--- | :--- | :--- |
| **Codex** | 15분 주기 대화창 폴링, 장문 로그 직접 열람 | 백그라운드 폴링 전면 금지. 올라마가 디스크에 발행한 60줄 브리핑(`codex_brief.md`)만 1턴에 섭취하고 판정. |
| **Claude Code** | 무한 대기 루프, 세션 상주 대기 | 세션 대기 중 주기적 API 호출 금지. 파일럿 실행 결과(`summary.json`)가 `mailbox/inbox/claude/`에 도착할 때만 1회 기상. |
| **Antigravity** | 15분 주기 유료 모델 cron 모니터링 | 유료 모델 기반 cron 스케줄 영구 정지(task 취소). 로컬 올라마 스크립트 기반 감시관으로 전면 이관. |

### 5.2. Codex 복귀 시 공식 인수 및 영구 정본화 절차
