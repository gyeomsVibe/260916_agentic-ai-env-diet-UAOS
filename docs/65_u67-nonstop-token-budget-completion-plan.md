# U67 무중단 토큰예산 완성 계획

## 현재 판정

U63~U66은 상태 보존, 무중단 전달, 이중 유료 기상 차단을 구현했지만 프로젝트 완성은 아직 아니다. 집중 인수 61개는 통과했으나, 이번 감사에서 작업자 호출 자체가 멈추는 Windows 인코딩 결함과 계약 토큰 상한이 실제 Claude 고정 컨텍스트보다 작은 문제를 재현했다. Ollama도 좁은 JSON 추출에서 같은 형식 위반을 두 번 반복했다. 따라서 “항상 토큰을 아낀다”와 “끝까지 멈추지 않는다”는 아직 `UNMEASURED`이며, 작업자 성공 문구만으로 DONE 처리하지 않는다.

## 비판 감사 결과

1. 기존 프로젝트 매뉴얼은 U45의 push 승인을 현재 작업으로 이전할 수 있었다. U67 매뉴얼은 행동별 최신 승인만 유효하도록 고쳤다.
2. Claude 감사 1차는 답변의 U+2014를 cp949로 출력하다 실패했다. UTF-8 환경 재시도는 acceptance exit 0이었지만 총 계약 토큰이 485,172로 12,000 상한을 넘어서 결과를 폐기했다. 변경 파일은 0개다.
3. Ollama `qwen2.5-coder:7b`는 같은 입력에서 두 번 모두 원시 JSON 대신 코드펜스를 반환했고 중복 항목도 만들었다. 이 digest의 JSON 추출 자격은 `REJECTED`; 유료 모델로 자동 승격하지 않는다.
4. U66과 U65-G의 고정 집중 인수는 Codex가 직접 61/61 통과했다. 생산 코드에서 테스트 이름·러너를 읽어 동작을 바꾸는 분기는 발견하지 못했다.
5. 원격 main은 U65까지만 포함하고 U66/U65-G/U67은 로컬 브랜치다. push·배포는 이번 지시의 무승인 범위에 포함시키지 않는다.

## 완료 순서

- U68: Claude worker UTF-8 출력 결함을 0토큰 apply와 cp949 재현 시험으로 고친다.
- U69: 유료 호출 전 컨텍스트·cache-read 바닥과 계약 상한을 비교하는 입장 관문을 설계·구현한다.
- U70: Ollama는 작업유형·모델 digest별 자격을 다시 측정하고, 결정적 추출보다 이득이며 스키마를 통과한 좁은 작업만 허용한다.
- U71: 세 도구 상태 전이와 우편함을 실제 병렬 프로세스로 끝까지 돌려 중복 작성·이중 유료 기상·사용자 릴레이가 0인지 확인한다.
- U72: 유효 표본 10개로 품질·유료/로컬 토큰·벽시계·재작업을 대조해 완성 여부를 판정한다.

## Ollama 최적 사용 규칙

매 단계는 `결정적 명령 → 자격이 유효한 Ollama 기계 작업 → 필요한 경우에만 유료 작업자` 순서로 라우팅한다. Ollama는 파일 지도, 짧은 요약, 정확한 치환, 고정 스키마 추출만 후보이며 설계·판정·승인은 금지한다. 출력은 스키마, 중복, 원문 심볼, 입력 SHA를 결정적으로 확인하고, 같은 원인 두 번 실패하면 해당 `(model digest, task type)`을 REJECTED로 고정한다. 로컬 토큰·시간·전력은 0비용으로 기록하지 않는다.

## 완료 관문

P1 0, 같은 단계 단일 작성자, ACK_ONLY 유료 호출 0, 편지 1통당 유료 turn 1 이하, 전체 회귀 exit 0, 3배 벽시계 회귀 0, 테스트 고정 부분 test-fitting 0, 사용량 장부 누락 0, 실제 절감 대조 표본 10개가 모두 필요하다. 하나라도 없으면 상태는 REVIEW 또는 UNMEASURED다.
