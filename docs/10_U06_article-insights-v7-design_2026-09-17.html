MIA Strategic Report · U06

코드를 덜 읽고도
책임지는 AI 작업환경

“아직도 코드를 읽나요?”가 던진 질문을 Codex–Antigravity 운영 규칙으로 번역한 사용자용 보고서. 핵심은 코드 읽기의 폐지가 아니라, 의도와 검증을 더 강한 형태로 보존하는 것입니다.

기준일 2026-09-16 대상: 비전문 사용자 형식: 핵심 우선·자동 진행

한 문장 결론

사람이 모든 코드를 읽는 부담을 없애려면, AI에게 더 많은 문서를 먹이는 것이 아니라 목표·결정 근거·검증 시나리오를 분리하고 필요한 순간에만 정확히 공급해야 합니다.

우리 환경에서는 Codex가 의도와 검증 계약을 소유하고, Antigravity가 단계별 전용 대화창에서 구현·조사·테스트를 무승인 수행하는 구조가 가장 맞습니다.

링크 확인 결과

사용자가 준 GeekNews ID 33727은 확인되지 않았습니다. 동일 제목의 실제 페이지는 33735이며, 원문은 Marek Chotoborski의 글입니다. 공유 링크와 해당 요약을 같은 기사로 분석했습니다.

1. 기사가 말하는 두 가지 개발 방식

가속형 개발자

AI가 코드를 많이 만들더라도 사람이 구현을 이해하고, 변경 결과를 설명할 수 있는 상태를 유지합니다.

  • 장점: 장애 대응과 장기 유지보수에 강함
  • 비용: AI의 생성 속도를 사람의 읽기 속도가 따라가지 못함
  • 부채: 이해가 따라가지 못하면 인지 부채가 쌓임

바이브코더

구현을 AI에 맡기고 사람은 원하는 동작, 제약, 결과의 합격 여부에 집중합니다.

  • 장점: 높은 생성 속도와 폭넓은 자동화
  • 비용: 좋은 명세·시나리오·평가 하네스가 필요함
  • 부채: “왜 그렇게 만들었는지”가 사라지는 의도 부채

우리가 택할 제3의 방식

사용자가 코드를 전부 읽지도, AI를 맹신하지도 않습니다. Codex가 의도·위험·검증을 구조화하고, Antigravity가 구현하며, 결정적 테스트와 위험 표본만 Codex가 확인합니다. 읽기의 대상을 코드 전체에서 “중요한 결정과 실패 증거”로 옮깁니다.

2. 모르는 것을 모르는 사용자가 놓치기 쉬운 것

1

작동한다고 맞는 것은 아니다

테스트가 통과해도 사용자가 원한 문제와 다른 문제를 풀 수 있습니다. 먼저 검증해야 할 것은 코드보다 목표입니다.

2

코드에는 이유가 남지 않는다

expiry = 6h를 읽어도 그것이 요구사항인지, 관례인지, AI의 추측인지 알 수 없습니다. 결정 근거를 별도로 보존해야 합니다.

3

더 많은 맥락은 더 많은 진실이 아니다

과거 문서와 폐기된 결정을 한꺼번에 넣으면 AI는 낡은 내용을 현재 규칙으로 오해합니다. 컨텍스트에는 유효기간과 권위가 필요합니다.

4. 컨텍스트는 창고가 아니라 작업대다

현재 작업에 필요한 정보만 작업대에 올리고, 나머지는 검색 가능한 보관소에 둡니다. 삭제가 아니라 선택적 로딩입니다.

Tier 0 — 항상: 사용자 목표, 현재 승인 경계, 활성 카드
Tier 1 — 단계: 허용 파일, 인수 기준, 직접 의존 결정
Tier 2 — 필요 시: 관련 설계·과거 장애·도메인 자료
Archive — 기본 제외: 오래된 로그, 폐기 설계, 완료된 단계 전문

각 항목: authority + scope + created_at + supersedes + expires_at

금지할 패턴

  • “관련 있어 보인다”는 이유로 docs 전체를 프롬프트에 넣기
  • 오래된 보고서의 결정을 현재 규칙보다 우선하기
  • 요약만 남기고 원문 포인터·근거를 버리기
  • 작업자가 자기 출력을 요약한 문장을 완료 증거로 사용하기

6. 사용자에게 보여줄 보고의 기본값

기본 화면 — 7줄 이내

  1. 결과
  2. 무엇이 바뀌었는지
  3. 검증 결과
  4. 남은 위험
  5. AI가 다음에 자동 수행할 단계

사용자 행동이 없으면 “할 일 없음”이라고 명시합니다.

상세 근거 — 접어서 보관

긴 로그, 전체 조사, 테스트 전문은 파일·작업 카드·링크로 남깁니다. 사용자가 요청하거나 실패 원인을 판단할 때만 펼칩니다.

짧게 쓰는 것과 증거를 버리는 것은 다릅니다.

7. 무승인 자동 진행 계약

상황AI 행동사용자 개입
카드 범위 안 조사·편집·테스트계속 진행없음
검증 실패같은 오류 지문 최대 2회 보완 후 재계획없음

8. 코드 리뷰를 없애지 말고 검증을 재배치한다

StrongDM의 Software Factory는 사람이 코드를 쓰거나 전통적으로 리뷰하지 않는 대신, 코드 밖의 행동 시나리오와 디지털 트윈으로 결과를 검증합니다. 여기서 배울 점은 “코드를 보지 말자”가 아니라 검증 장치 없이는 코드를 보지 않는 선택을 할 수 없다는 것입니다.

Low risk

포맷·문서·격리된 변환. 스키마와 자동 테스트가 통과하면 완료.

Medium risk

기능·리팩터링. 시나리오, 회귀 테스트, 위험 diff 표본 검토.

High risk

인증·결제·데이터·배포. 전체 위험 검토와 별도 사용자 승인.

9. v7에 고정할 최소 규칙

  1. Codex가 하나의 계획·상태·예산·최종 판정을 소유한다.
  2. 실제 수행은 `[U##]` 전용 대화창의 단일 소유자가 한다.
  3. Antigravity 위임은 범위 안에서 무승인 자율 실행한다.
  4. 대화창은 정본이 아니며 `.coord` 원장을 가리키는 포인터다.
  5. 컨텍스트는 최소 로딩하며 오래된 자료는 권위·만료·대체 관계를 확인한다.
  6. 코드와 별도로 의도·결정 근거·가정·폐기 조건을 보존한다.
  7. 완료는 설명이 아니라 외부 검증 receipt로 판정한다.
  8. 사용자 보고는 짧게, 상세 증거는 파일에 보존한다.
  9. 사용자 행동이 필요하지 않으면 AI가 다음 단계를 자동 진행한다.
  10. 삭제·배포·push·결제·계정/권한 변경만 행동별 승인을 받는다.

10. MIA 결정

GO

컨텍스트 계층화, intent ledger, proof ladder, 짧은 사용자 보고, 단계별 전용 대화창, 정상 단계 자동 진행을 v7 설계에 반영합니다.

아직 주장하지 않을 것

토큰·시간 절감률은 로컬 A/B 벤치마크 전까지 UNMEASURED입니다. “모든 코드를 읽지 않아도 안전하다”는 보편 결론도 내리지 않습니다.
