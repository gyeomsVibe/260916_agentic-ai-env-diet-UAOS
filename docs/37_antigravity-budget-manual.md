# Antigravity 작업·검증·임시 대행 매뉴얼

상태: 유지(maintained). 권위: `docs/27_token-budget-routing-policy.md`와 `.coord/PLAN.md`.

1. 시작 전에 현재 카드·원장·QUIET_LOCK·원본 작성자를 확인한다. 같은 단계의 Codex·Claude·Ollama가 원본을 쓰는 중이면 실행하지 않는다. 읽기 전용 자문도 지정 범위·완료 기준·중지 조건을 받는다.
2. 평상시 기본 역할은 독립 검증이다. 구현을 맡을 때는 작은 카드 하나, 허용 파일과 결정적 인수, 원격 사용량 상한, 실패 시 중지 조건을 먼저 받는다. 지휘 도구의 잔여율이 낮다는 이유만으로 총괄 권한을 넘겨받지 않는다.
3. Codex와 Claude 둘 다 **실제 제한·부재**임이 최신 증거로 확인된 경우에만 임시 대행을 시작한다. 이유·시각·범위·승인 경계와 복귀 재검토 목록을 카드에 기록한다. 계정 상태가 `UNKNOWN`이면 부재로 추정하지 않는다. 대행 중에도 사용자 승인 경계를 상속받지 않는다.
4. 요약·변환·정확한 파일 패치는 Ollama 전화기로 먼저 처리한다. 지시문은 입력 해시·정확한 치환·출력 경로·인수 명령을 고정한다. Ollama의 자기 보고를 판정으로 쓰지 않는다. 구체성이 낮은 설계·반례 탐색은 Antigravity가 직접 하되 한 작업마다 범위를 제한한다.
5. `pilot run --worker agy`를 사용할 때는 `--source`를 좁히고 한 번에 한 카드만 실행한다. 수십만 토큰과 변경 0건 같은 결과는 비용 게이트 실패다. 자동 원격 승격은 카드가 허용한 경우만 쓰고, 실패 1회 후에는 계약을 축소한다. 같은 원인 3회는 중단한다.
6. 결과에는 실행 ID, 원본/후보 해시, 정확한 diff, 테스트 명령·exit, 입력/출력/캐시 토큰, 벽시계, 잔여 위험을 남긴다. 증거가 없거나 출력이 비면 성공을 주장하지 않는다. 작성자와 다른 검증자가 실제 반례를 실행해야 `REVIEW`에서 `DONE`으로 간다.
7. 복귀한 Codex/Claude에게는 카드와 60줄 이하 브리핑을 한 번 인계한다. 변경 없는 상태에서 알림을 반복하지 않는다. Codex가 제한·부재면 `coord notify`/`codex queue`를 호출하지 않고 디스크 기록만 남긴다. P1 알림은 현행 U23 복구·중복 방지 결함이 해결되기 전까지 전달 보증으로 취급하지 않는다.

작업별 기록: `work_id`, 작업자, 로컬 호출 여부와 이유, 원격 호출 횟수, 토큰, 벽시계, 인수 결과, 독립 검증자를 남겨 10건마다 원격 승격률과 P1을 검토한다.

RSI 인계: 호출마다 원격 입력·출력·캐시 토큰과 벽시계·실패를 [장부](../.coord/usage/README.md)에 남긴다. [RSI 정본](31_evidence-gated-rsi-for-uaos.md)의 가설·반례는 제안할 수 있으나 자신의 구현을 자기 점수로 `DONE` 처리하지 않는다. 증거가 비어 있으면 `UNKNOWN`이다.
