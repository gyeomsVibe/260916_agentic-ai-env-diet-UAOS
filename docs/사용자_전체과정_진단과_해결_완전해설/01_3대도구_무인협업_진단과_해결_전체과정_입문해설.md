# [UAOS] 3대 AI 도구 무인 협업 체제: 진단, 해결, 그리고 자율 병합의 모든 것

> **대상 독자**: "AI 도구들이 어떻게 서로 대화하고 일하는지 전혀 모르는 초보자"부터 "시스템 엔지니어링 설계를 검증하려는 전문가"까지 모두를 위한 완전 해설서입니다. 전문 용어는 일상적인 비유와 함께 반드시 영문 원어를 병기(전문용어 병기 원칙)했습니다.

---

## 1. 한눈에 이해하는 10초 요약 (ELI10: 초등학생도 이해하는 비유)

우리가 사용하는 AI 도구 3인방(**Antigravity**, **Claude Code**, **Codex**)과 로컬 모델(**Ollama**)은 마치 **"각자의 방에서 일하는 천재 개발자들"**과 같습니다.

- **예전의 문제**: 방마다 문이 닫혀 있어서, 한 AI가 작업을 끝내도 다른 AI에게 알릴 방법이 없었습니다. 그래서 사용자가 일일이 "클로드야, 안티그래비티가 작업 끝냈으니 확인해"라고 복사-붙여넣기(심부름)를 해야 했고, 깜빡 잠들면 모든 작업이 멈췄습니다.
- **지금의 해결**: AI들의 방문 앞에 **"비용이 0원인 빨간 우체통(디스크 사서함, Maildir)"**을 달았습니다. 편지가 도착하면 0원짜리 초인종이 **"띵동"** 울리고(사서함 감시, `coord watch`), AI가 잠에서 깨어나 작업을 이어받아 끝마칩니다. 사용자가 자는 동안에도 셋이서 **밤새 쉬지 않고 릴레이(티키타카, Continuous Turn-Taking)**를 합니다.

---

## 2. 왜 이런 문제가 생겼었나? (핵심 진단: Root Cause Analysis)

### [진단 1] 유료 API의 주기적 조회(Polling)는 돈 낭비다
- **문제점**: 상대방이 답장을 보냈는지 확인하기 위해 1분마다 유료 AI를 깨우면(Cron/Polling), 아무 일도 안 했는데 한 달에 수십만 원의 토큰 비용(Token Cost)이 청구됩니다.
- **해결책**: 유료 AI를 깨우지 않고, 컴퓨터의 운영체제(OS)가 2초마다 파일이 도착했는지만 조용히 살피는 **"0토큰 파일 감시(coord watch)"** 기술을 도입했습니다. 464통의 편지를 뒤져도 0.008초밖에 안 걸리고 CPU 점유율은 0.4% 미만, 사용 토큰은 정확히 **0원**입니다.

### [진단 2] 사람이 왜 PR(Pull Request) 병합 버튼을 눌러야 하는가?
- **문제점**: AI들이 코드를 다 짜고 테스트를 100% 통과해도, 깃허브(GitHub) 병합(Merge) 권한을 사람에게만 넘겨두면 사람이 외출하거나 잠들었을 때 파이프라인 전체가 멈춥니다(Stall).
- **해결책**: 윤겸스 대표님의 고정 내규(v7.5.4)에 따라 **"1순위 Antigravity, 2순위 Codex"**로 자율 병합 순위를 확정했습니다. 테스트와 검증 통과 영수증(Receipt)이 첨부된 PR은 사람이 없어도 Antigravity가 직접 원격 저장소에 자율 병합합니다.

### [진단 3] 20통 일일 상한(Daily Cap)과 편지 누락 현상
- **문제점**: 10월 4일, 헤드리스 자동 응답(Headless Auto-answer)이 하루 20통 상한에 걸리면서 Claude가 "감사 답장을 못 받았다"며 자정까지 대기하는 정체(Deadlock)가 발생했습니다.
- **해결책**: explicit `ACTIONABLE`(실행 필요) 편지는 본문 단어와 무관하게 100% 즉시 깨어나도록 조건식(`wants_turn`)을 단일화하고, Stop Hook(작업 정지 차단 관문)을 통해 대기 정체를 원천 차단했습니다.

## 3. 구조화된 전/후 비교 (Structured Few-Shot Case Studies)

### [사례 1: PR 병합 처리]
- **과거 (Before)**: Claude가 PR #128 생성 → "사용자님, PR #128을 병합해 주세요" 출력 → 사용자가 확인할 때까지 몇 시간 동안 전 도구 올스톱.
- **현재 (After)**: Claude가 PR #128 생성 → Antigravity에게 감사 요청 편지 발송 → Antigravity가 단위 테스트 100% 통과 확인 후 `uaos coord merge`로 **자율 병합 완료** → Claude가 다음 작업 즉시 자동 착수.

### [사례 2: 소리 없는 야간 작업의 불안감]
- **과거 (Before)**: 도구들이 백그라운드에서 일해도 편지가 오갔는지, 에러가 났는지 사람이 화면을 계속 쳐다보지 않으면 알 수 없음.
- **현재 (After)**: U143 사운드 링(Sound Ring) 탑재. 중요 편지가 도착할 때마다 윈도우 기본 알림음(MessageBeep)이 1회 비동기로 울려 귀로 진행 상태를 파악 가능 (1분 내 다량 편지는 소음 방지를 위해 1회로 병합 디바운싱).

### [사례 3: 4단계에서 11단계 표준 전략으로의 진화 (MIA Strategic)]
- **과거 (Before)**: 대략적인 [조사 → 기획 → 실행 → 검증] 4단계로 진행하여, 사전에 공식 문서나 깃허브 실측을 건너뛰고 코딩부터 하다가 파일이 깨지는 사고 발생.
- **현재 (After)**: **엄격한 11단계 프레임워크** 정본화.
  `[0. 사전 웹딥리서치(공식문서 필수) → 1. 기획 → 2. 검증 → 3. 큰계획 → 4. 검증 → 5. 세부계획 → 6. 검증 → 7. 구현계획 → 8. 검증 → 9. 구현 → 10. 디버깅 및 최종검증]`
  0단계 웹 리서치 근거가 없는 코드는 커밋 관문(`commit-msg`)에서 원천 거부됨.

## 4. 3대 도구의 역할 분담과 위계 (Authority Hierarchy)

1. **Codex (지휘자, Conductor)**: 마스터 계획 관리, 최종 승인 및 방향 결정 (단, 한도 도달 시 Claude에게 지휘권 위임).
2. **Claude Code (부지휘자, Subconductor)**: Codex 부재 시 전권 대행, 격리 워크트리(`worktree`) 기반의 핵심 기능 고속 구현.
3. **Antigravity (조종석 및 독립 감사자, Cockpit & Auditor)**:
   - **사용자 컨트롤 인터페이스 1순위**: 사용자와 한국어로 소통하는 대화창구 총괄.
   - **독립 검증(Independent Audit)**: 타 도구가 짠 코드를 제3자 입장에서 반례(Counterexample) 검증.
   - **자율 병합 1순위**: 검증 통과된 PR을 사람 대신 깃허브에 직접 병합.
4. **Ollama (로컬 전자계산기, Local Calculator)**: 주관적 판단이나 설계를 하지 않고, 300줄 이상 긴 파일 읽기 지도(`local_read_map`), 로그 요약, 단순 치환만 수행하는 **비용 0원의 무제한 일꾼**.

---

## 5. 결론 및 향후 전망

UAOS는 이제 사람이 일일이 감시하고 명령하지 않아도, 세 AI 도구가 파일과 우편함을 통해 **스스로 증거를 확인하고, 승인하고, 코드를 병합하며, 시스템을 재설치하는 완전 자율 오케스트레이션 단계**에 도달했습니다. 사용자는 자리에 앉아 결과 보고만 간결하게 확인하시면 됩니다.
