## Findings

### P2-1 (blocking) A window-lock timeout after a successful paid turn turns the delivery into a failure or a crash, so the letter is re-dispatched (duplicate paid turn)
The PR adds cross-process locks with a 2.0 s ceiling (`WINDOW_LOCK_TRIES=200 x 10 ms`, raising `TimeoutError("WINDOW_LOCK_TIMEOUT:...")`)
to every window bookkeeping write, and the global `registry_index` lock is held across `_retry(tmp.replace)` (itself up to ~2 s on
Windows sharing violations), so contention under parallel lanes can exceed the ceiling. These writes run AFTER the remote turn:
- `deliver.py` `_deliver_unlocked`: `release_window_lease(...)` in the `finally` and the Codex fallback `record_window(...)` run before
  `_write_receipt(accepted, ...)`. A raise skips the accepted receipt, the outer `finally` nacks the claim back to the inbox, and
  `deliver()` raises. Probe A (release raises TimeoutError, runner succeeded once): `turns_run=1 outcome=raised TimeoutError accepted=0 inbox=1`.
- `deliver.py` `_deliver_to_claude_locked` failover `record_window(...)` runs after the successful retry; `_deliver_to_claude` catches
  `TimeoutError` and returns `DELIVERY_FAILED`. Probe B: `turns_run=2 outcome=returned DELIVERY_FAILED:WINDOW_LOCK_TIMEOUT:card_U301 accepted=0`.
- `agy_dispatch.py` `_dispatch_owned`: `acquire_window_lease` runs after `_reserve` (unit spent) outside the try, and
  `release_window_lease` in the `finally` runs before `_keep_reply`; a raise loses the paid Antigravity answer (no FAILED/ANSWERED row).
Required: post-success bookkeeping (lease release, failover record, registry mirror) must never change the delivery outcome: catch
`(TimeoutError, OSError)` there, write the accepted receipt first, and record a `WINDOW_BOOKKEEPING_FAILED` attempt receipt; a
lease-acquire timeout before dispatch should return a structured refusal instead of raising. Add a test that injects the timeout
(as in the probe) and asserts exactly one accepted receipt and no re-dispatch.

### P2-2 (blocking for the stated acceptance) The bounded pool is not wired into any runtime path
`acquire_topic_window`, `active_topic_windows`, `set_window_in_flight`, `window_lease` and `agy_dispatch._recover_dead_dispatcher`
have no production caller (grep over `v7_harness/`, `uaos_everywhere/`: only definitions and tests). `coord window` still calls
`open_window`, which uses the exact card (a sub-card such as `U275-R8` opens its own window, no cap, no LRU, no 70k rotation).
In real use only the `window_for` topic fallback, the leases and the Claude lock sharding take effect. The PR body still claims the
3-per-tool pool, "burst coalescing into [UAOS topic-batch]" (removed in R2) and "6/6 PASS". Required: either route `coord window`
(and any open path) through `acquire_topic_window` with a CLI test, or narrow the PR body/card acceptance to what is wired and mark the
pool as library-only pending a use receipt.

### P3
- P3-1 `windows.py` `window_for`: the two tail branches after the topic fallback are unreachable duplicates of `_is_entry_active` (dead code).
- P3-2 `_prune_entry_leases` re-stamps a lease whose `pid` is not an int with the current writer's PID, so a malformed lease never expires (slot stays in-flight; fails closed, but permanently). Drop malformed leases instead.
- P3-3 `set_window_in_flight(False)` pops another process's live lease when the caller has none (`elif live: pop(next(iter(live)))`), which could let the pool evict an in-use window if this helper is ever wired.
- P3-4 `_sync_registry_index` silently drops the mirror update after `PermissionError`, so `.coord/windows.json` can go stale without a receipt.
- P3-5 `MAX_ACTIVE_WINDOWS_PER_TOOL = 3` is justified by "3 parallel execution lanes", but the current OS defines 5 process lanes (U287/U292); the number needs a current rationale. `RECOVER_WAIT_S = 0.2` states its arithmetic, not why 0.2 s.
- P3-6 Claude topic lock keys on the topic, not on the session id: two topics recorded on the same session would resume it concurrently (mitigated by `session_busy`, then by the new failover). Card-window failover also replaces a visible desktop session id with a fresh headless one (U129 visibility); acceptable per the R1 request, but worth a receipt.
- P3-7 `agy_dispatch._recover_dead_dispatcher` duplicates `deliver._recover_lock` and is unused.
