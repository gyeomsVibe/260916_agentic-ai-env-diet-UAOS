## Findings (severity first)

1. **P1 — runtime-sync keypoint guard is blind to merge commits.** `merge_route.sync_runtime_after_merge` lists changed files with `git show --name-only --pretty=format: <head>`. For a merge commit `git show` prints the combined diff, which lists only files that differ from *every* parent. Reproduced on main: `git show --name-only e030527` lists 1 file (`deliver.py`); `git diff --name-only e030527^1 e030527` lists 18 (incl. `stall.py`, `stop_gate.py`, `watch.py`). A PR touching a codex-exclusive keypoint merged with a merge commit therefore passes `is_codex_exclusive_keypoint` and reinstalls the runtime without Codex return review. Today it is mitigated (`.coord/presence/runtime_reinstall_hold.json` exists and no caller passes `sync_runtime=True`), but the guard is the reason the function exists. Fix: `git diff --name-only <head>^1 <head>` (or `git show -m --first-parent --name-only`), plus a test with a real 2-parent merge commit whose second parent touches a keypoint path. No test covers the keypoint branch or a successful sync.
2. **P2 — a preempted non-waking watcher can still consume a wake.** The token re-check runs only at the top of each loop iteration. Between a `--wakes-session` watcher overwriting the lock and the old watcher's next check, the old watcher can reach `claim_wake` for an ACTIONABLE letter, claim it, and return it to a non-waking caller: the interactive session never wakes for that letter. Fix: re-check the lock token immediately before `claim_wake` (and before returning a found letter). `_take_locks` is still check-then-write (pre-existing), so two waking watchers can both "preempt"; it self-heals via the token check, but neither case has a real two-process test. The current test is single-process with `timeout_s=0.0` and never exercises the preempted watcher's exit.
3. **P2 — Stop hook can block up to ~20 s.** `stop_gate.gate` now calls `replan_on_quota_limit` and, on DONE, `finalize_schedule_closeout`, each under `_exclusive(stall.lock)` with `LOCK_TIMEOUT_S = 10.0`. Exceptions are swallowed, but the wait is not: under contention one Stop hook can wait 10 s + 10 s, near the hook timeouts behind the U264 incident. Fix: a short/non-blocking lock attempt in the hook path (skip; the next turn replans).
4. **P3 — closeout is not idempotent.** Once CLOSED_OUT, every later Stop with `next_step == DONE` rewrites the receipt (`closed_at`, `closed_out_by`) and deletes all tools' `stop_gate_<tool>.json` again. Return early when `schedule_state == "CLOSED_OUT"`.
5. **P3 — `claude -p` judge route has no hard spend cap.** `build_claude_command` passes no `--max-budget-usd`; the budget is checked only after the call by `cost_gate`. The real CLI flags (`--json-schema`, envelope `result`/`usage`) are exercised only with a mocked runner: real-use UNKNOWN.
6. **P3 — naming.** `quorum_When_codex_active` (mixed case) in `judge.run_judge`.
7. **P3 — intended behaviour change, for Codex re-review.** Keypoint contracts now refuse any non-codex judge even when Codex is away (previously agy could act for an away Codex): consistent with U257, but keypoint cards wait for Codex's return. The Stop hook now auto-reassigns Codex-owned READY/PLANNED non-keypoint phases while Codex is LIMITED (with `rerouted_from` receipts).
