## Recommendation

- **Lever 1 (Claude Code calls reduction via deterministic apply)**: Offload exact file changes to `worker: apply` and batch scripts instead of interactive tool iterations. Each skipped Claude call saves ~140k cached read tokens (~14k read-equivalent tokens) based on U95-B transcript metrics. Source: Q1-1, Q6-1. Risk: Low; deterministic syntax validation prevents regressions.
- **Lever 2 (Claude Code pre-tool deny guard for whole-file reads)**: Implement a PreToolUse hook in Claude Code that denies whole-file reads over 300 lines and forces targeted line ranges or Ollama digests. Expected effect: Prevents 20k–50k token spikes per read that persist across remaining calls. Source: Q1-1, Q5-2. Risk: Low; fallback to line-range reading is always available.
- **Lever 3 (Claude Code auto-compaction tuning via environment override)**: Configure `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50` or set `/autocompact 150k` in user settings to trigger compaction before context reaches 215k. Expected effect: Reduces average context per call from ~142k to ~110k (saving ~22% on total cache reads across long sessions). Source: Q1-1, Q6-1. Risk: More frequent summarizations may lose minor historical context details.
- **Lever 4 (Codex instruction file truncation audit)**: Ensure the combined size of `AGENTS.md` and hierarchical rules stays strictly below `project_doc_max_bytes` (32 KiB) or increase the limit in `~/.codex/config.toml`. Expected effect: Prevents silent truncation of critical rules without paying unnecessary tokens for unneeded documentation. Source: Q2-1. Risk: UNMEASURED; larger doc budgets consume slightly more base tokens per call.
- **Lever 5 (Codex reasoning effort adaptation)**: Use `reasoning_effort = "low"` or `"medium"` for routine implementation cards, reserving `"high"` only for difficult architectural proofs. Expected effect: Cuts output reasoning tokens by 30%–60% on mechanical tasks. Source: Q2-4. Risk: Low; difficult tasks can escalate effort on failure.
- **Lever 6 (Antigravity ephemeral hook messaging)**: In Antigravity, pass dynamic briefing and handoff notices via `PreInvocation` `injectSteps` using `ephemeralMessage` rather than persistent session appends. Expected effect: Notice disappears after the turn, adding 0 tokens to subsequent turn history. Source: Q3-2. Risk: None; persistent state is maintained on disk (`.coord/mailbox`).
- **Lever 7 (Offload mechanical classification and extraction to local Ollama)**: Route deterministic extraction, diff syntax verification, and repetitive file summaries to local models (`qwen2.5-coder:7b`) with 0 paid tokens. Expected effect: Up to 98% cost reduction for mechanical steps as proven by FrugalGPT and RouteLLM benchmarks. Source: Q4-1, Q4-2. Risk: Local model output formatting errors (mitigated by strict schema and deterministic acceptance gates).
- **Lever 8 (Enforcement by code and hooks over long prompt rules)**: Replace long textual negative constraints in instruction markdown with hard PreToolUse hook blocks and commit gates. As demonstrated in LIFBench and BiasBusters, LLMs suffer instruction decay under long contexts; deterministic guards never fail closed. Source: Q5-1, Q5-2. Risk: None; guarantees adherence to security and budget boundaries.
- **Lever 9 (State and memory persistence on disk over in-context memory)**: Maintain plan progress and cross-tool relays on disk (`.coord/PLAN.md`, `.coord/mailbox/`, `shared_desk`) instead of conversational history, following MemGPT and SWE-agent principles. Expected effect: Allows conversations to be cleared or compacted at will with 0 loss of project continuity. Source: Q6-1, Q6-2. Risk: Requires disk I/O and atomic locking for concurrent multi-process access.
- **Lever 10 (Tool search and deferred schema loading)**: Keep MCP tools in deferred mode so only essential core tools (`read`, `edit`, `run_command`) occupy active context, loading specialized tools only when invoked. Expected effect: Cuts initial prompt overhead by 15k–30k tokens per call. Source: Q1-3. Risk: Slight latency overhead on the first turn a deferred tool is searched.

## Not found

- Whether Claude Code supports a user-configurable 1-hour prompt cache TTL via environment variable or CLI flag: The Anthropic API supports 1-hour cache duration at 2x write pricing (`cache_control: {"type": "ephemeral", "ttl": "1h"}`), but Claude Code currently manages caching internally and defaults to the standard 5-minute TTL without an exposed configuration key for 1-hour TTL.
- Official breakdown of how Claude Code plan usage limits (5-hour window and weekly limits) weigh cached input tokens versus uncached input tokens: The public documentation specifies API pricing ratios (cache read = 0.1x, cache write = 1.25x), but the exact internal weight applied to plan usage meters remains unstated.
