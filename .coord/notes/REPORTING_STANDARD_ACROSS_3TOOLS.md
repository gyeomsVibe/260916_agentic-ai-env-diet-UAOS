# [보고체계 표준] 3대 AI 도구 상시 상호 보고 및 지휘 연동 규약

> 발행: 2026-10-03  
> 대상: Codex (Conductor), Claude Code (Deputy), Antigravity (Executor/Auditor)

---

## 1. 근본 결함 및 교훈
- **단순 수신 확인(ACK) 남발로 인한 지휘 마비**:
  - 편지에 `verdict_requested=yes`나 구체적 요청 사항 없이 단순 수신 확인만 담아 보낼 경우, 수신한 지휘자(Codex)는 "요청사항 없음, 대기 및 감시 재가동"으로 턴을 끝내 버려 작업이 멈추는 병목이 발생함.
- **스레드 오배송으로 인한 사용자 화면 고착**:
  - 메시지가 사용자 활성 대화창이 아닌 백그라운드 스레드로 들어가면, 사용자는 진행 상황을 보지 못하고 시스템이 멈춘 것으로 오인함.

---

## 2. 3대 도구 상시 보고 규약 (3-Tool Reporting Standard)

1. **지휘 편지의 4대 필수 요소**:
   - `[식별]` 정확한 `ACTIONABLE_DELTA` 및 `verdict_requested=yes` 명시.
   - `[완료 증거]` 변경 파일(diff), 테스트 결과(exit 0, PASS 수치), 영수증 ID.
   - `[판정 대상]` 지휘자가 승인/거부해야 하는 명확한 작업/산출물 명시.
   - `[다음 행동]` 판정 즉시 착수할 후속 작업(Next Card).

2. **단순 확인(ACK)의 침묵 원칙**:
   - 상태 변화가 없거나 단순 확인 메시지는 대화 세션을 깨우지 않고 조용히 우편함에만 기록 (`ACK_ONLY`).

3. **사용자 활성 대화창 직결 원칙**:
   - 모든 대화형 편지는 현재 사용자가 주시하고 있는 활성 창(세션 ID 매핑)으로 직접 전달되어, 사용자가 대화 흐름을 실시간으로 확인할 수 있어야 함.

4. **무승인 논스톱 실행**:
   - Safety 사람 전용 목록(데이터 삭제, 원격 푸시, 결제 등) 외의 모든 내부 의존성(리뷰, 승인, 테스트, 다음 카드 착수)은 사용자에게 묻지 않고 3대 도구 간에 연속적으로 완결함.
