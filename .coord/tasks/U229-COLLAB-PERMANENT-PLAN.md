# U229 협업 누락 — 사용자 오류 보고 및 영구 수정 계획

유지관리 문서. 2026-10-25 사용자 지시: 단독 작업을 UAOS 시스템 실패로 기록하고 영구 수정한다. 현재 요청에 따라 기존 제목·기록·RSI 작업을 먼저 마무리하고 아래 관문을 다음 단계로 연결한다.

## 확인된 실패

- Codex 내부 보조 에이전트의 작업을 Codex/Claude/Antigravity 사이의 실제 업무 분담과 혼동할 수 있었다. 두 구조를 같은 협업 실적으로 합산하지 않는다.
- Claude와 Antigravity가 구체적인 작업 지시를 요청했는데, 지휘자가 활성 단계의 역할·허용 범위·인수 명령·중단 조건을 두 네이티브 창에 제때 완결해 전달하지 못했다. 단일 작성자 규칙이 조율자 단독 수행의 면제가 된 것은 아니다.
- 게시/큐/자동 회신을 실제 작업 수신이나 파일 기반 감사로 취급할 위험이 있었다. 읽기 불가능한 agy-auto 회신은 파일 감사 증거가 아니다. 재개 시 같은 경로로 자동 회신을 다시 발생시킨 것은 비용 낭비로 기록한다.
- 제목만 병합된 PR187을 근거로 기록·RSI까지 포함한 U229 전체가 DONE으로 정합 처리됐다. 부모 카드의 원래 인수 범위가 완료 판정에서 사라졌다.

## 현재 분담

| 역할 | 담당 | 실제 상태와 경계 |
|---|---|---|
| 순서·범위·독립 최종 판정 | Codex | 현재 데스크, 기존 dirty 원본/다른 작성자 보존 |
| 최신 런타임 기반 안전한 기록 모듈 통합 | Claude | U229-B-CURRENTBASE 계약 발송. 네이티브 ACK 확인 전 착수 완료로 표시하지 않음 |

## 영구 수정 순서와 고정 인수

1. **공유 계약에 staffing 필드 추가**: conductor, implementer, independent_verifier, 각 네이티브 세션·작업트리·허용 경로·입력 해시·pass command·stop·상한·의존 상태. 역할을 겸하면 근거와 실제 제한 상태를 기록한다. 보조 에이전트 두 개를 다른 플랫폼 두 개로 표시하지 않는다.
2. **dispatch 이전 admission**: 실행 범위·담당이 없거나 작성자와 검증자가 같으면 시작 거부. 실행 가능한 동료에게 아무 일도 배정하지 않은 채 지휘자 단독으로 제품 변경을 시작하는 경로를 차단한다. 단일 파일의 작성자는 여전히 한 명이다.
3. **수신 상태 계약**: PUBLISHED/QUEUED/DISPATCHED/ACK/실행/검증 완료를 별도 상태로 고정한다. 주소가 다른 ACK, 단순 자동 회신, 존재하지 않는 산출물, 읽기 권한 없는 감사는 수신·검증 관문을 통과시키지 않는다.
4. **능력과 계약의 사전 대조**: 파일 검토 계약을 파일 도구가 막힌 자동 응답 경로에 보내지 않는다. 유효한 네이티브 수신 경로 또는 실제 다른 독립 검증 경로만 선택한다. 같은 실패를 다시 깨우는 대신 실패 영수증과 다음 의존성을 기록한다.
5. **부재와 복귀**: 실제 한도/부재이면 제한된 대체 역할과 진행 가능한 범위를 명시한다. 독립 검증이 불가능하면 변경은 격리에 두고 다른 준비 작업을 한다. UNKNOWN을 대행 승인이나 임의 역할 위임으로 바꾸지 않는다.
6. **완료 범위 고정**: 부모 카드의 모든 인수 항목에 증거를 연결한다. 제목 PR 하나를 기록·RSI 전체 완료로 확대하지 않는다. 부분 완료는 별도 상태로 표시한다.
7. **교체 설치 회귀 차단**: 새 패키지를 현재 런타임과 비교한다. `coord listen`, `usage`, 제목·docs/card 등 현재 기능의 canary를 모델 호출 없이 검증한다. 기능 누락을 발견하면 전체 오래된 런타임으로 덮지 말고 최신 기반의 정확한 추가 변경으로 복구한다.
8. **자동 감시**: 로컬 결정적 감시가 미배정/미수신/해시 변화를 탐지하고 의미 있는 변화에만 한 번 알린다. 협업 증명용 유료 ACK 루프나 유료 정기 폴링을 만들지 않는다.

필수 반례: 역할 없음, 동일 작성자·판정자, 다른 세션 ACK, 도구 없는 감사 경로, 만료된 능력·입력 해시, 동일 자원 두 작성자, 제목만 완료한 부모 카드, 재설치 중 listen/usage 누락, 제한 도구 재호출 루프. 원래 평가기를 약화하지 않고 새 admission 경계의 독립 검사를 먼저 고정한다.

## 승격 조건

세 도구의 실제 계약 소비와 독립 판정, 원래 고정 인수, 기능 보존 canary, 원장·원본 해시 보존이 필요하다. 이 문서는 **영구 수정 계획**이며, admission 코드가 이미 강제된다고 주장하지 않는다. 기존 U229 마무리 후 하나의 좁은 카드로 구현한다.
